# 草川たくや SNS便 朝納品便 6:45 JST（ローカルMac launchd・SNSルーティンv3・2026-07-23〜）

毎朝6:45に**そのままコピペ投稿できる完成短文原稿セット**を草川のDiscord DMへ直接納品する。メニュー選択制は廃止（v2）。返信が無くても草川の手元に毎日下書きが届くことが本ジョブの存在意義。**先に、昨夕納品への深夜返信が未処理なら返信処理を実行**してから、朝の納品を行う。

## 🔌 MCPツールの扱い（最優先・スキップ禁止）

このジョブは launchd の headless 実行のため、`mcp__claude_ai_Notion__*` と `mcp__claude_ai_Gmail__*` は **deferred（スキーマ未ロード）の状態で起動する**。
**deferred は「未接続」ではない。** スキーマが見えないだけで、ロードすれば通常どおり使える。

最初に必ず1回だけ ToolSearch を呼んでスキーマをロードすること:

```
ToolSearch query="select:mcp__claude_ai_Notion__notion-fetch,mcp__claude_ai_Notion__notion-search,mcp__claude_ai_Notion__notion-update-page,mcp__claude_ai_Notion__notion-create-pages,mcp__claude_ai_Notion__notion-query-database-view,mcp__claude_ai_Gmail__search_threads,mcp__claude_ai_Gmail__get_thread"
```

**ToolSearch を試す前に「未接続」「MCP不在」と判定して納品を中止することを禁止する。**
ToolSearch でロードした後、実際に呼んでエラーが返った場合にのみ、本物の接続障害として扱ってよい（その場合の縮退動作は「エラー時」節）。

# 共通セットアップ（毎回最初に実行）

1. Bashで `TZ=Asia/Tokyo date '+%Y-%m-%d (%a) %H:%M'` を実行し本日・曜日・時刻を取得。
2. Discord送受信は `python3 ~/.claude/scripts/sns-routine/discord_api.py` を使う:
   - 送信: `post "<text>"`（stdoutに送信msg_id）
   - 受信: `read <after_msg_id>`（is_user=trueが草川本人。attachments配列に写真等の添付情報）
   - 添付保存: `download <msg_id> <dir>`（写真を保存しパスを出力）
   トークンはスクリプト内部で処理されるため一切扱わない・出力しない。
3. 状態の正本は「📮SNS便ステータス」page `39dcf503-a68f-811b-bdd3-cce4e418187a`。更新は notion-update-page update_content（節単位の外科的置換）で行い、他節を壊さない。

# Step 0: 未処理返信の繰越処理

1. `_delivery_state.json`（前回納品のmsg_id）とステータスページ「処理済み返信msg_id」を読む。
2. Discord受信（after=前回納品msg_id）→ 本人メッセージのみ→処理済みを除外。
3. 返信があれば「返信文法」（leg_morning_reply.md と同一規則。本ファイル末尾の返信文法節参照）で処理してから次へ。無ければそのまま次へ。

# Step 1: 素材収集（毎回全部やる・ここの手抜きが「程度が低い提案」の直接原因）

1. **テーマ履歴**: `_theme_history.json` をRead。過去14日の採用テーマ・切り口一覧＝クールダウン対象（例外は手順4の草川投げ込み由来のみ）。
2. **Notion素材**: 📮候補パック「本日の候補」／📰ニュースダイジェスト当日分／ステータスページ（前回納品・処理済み返信）を読む。
3. **深夜の投げ込み**: Discord受信（after=昨夕の納品msg_id）で本人メッセージを読む（**読むだけ。リアクション・カーソル操作は絶対にしない**＝夜間intakeの管轄）。「発信:」タグの有無を問わず、活動メモ・感想も発信素材として扱う。attachmentsに画像（content_typeがimage/*）があれば写真素材として記録。
4. **iJAMPスキャン（Gmail・規約適合ルート）**: `mcp__claude_ai_Gmail__search_threads` で `from:ijamp.jiji.com newer_than:1d` を検索し、ヒットしたスレッドを get_thread で取得。全記事の見出しをスキャンして「亀山に接地できる新しい動き」を新風枠候補に挙げる。《市政コーナー》（他自治体事例）は新風枠の主力ソース。**⚠️著作権**: iJAMP本文の転載・引用は全面禁止。テーマの種としてのみ使い、採用時はStep 3で公開一次情報に乗り換える。
5. **追加WebSearch（新風枠の独自探索）**: 上記で「直近3日以内のホットな話題×亀山に新しい風」候補が見つからない/弱い場合、WebSearchを2〜3本まで実行（例:「自治体 <政策ドメイン> 新規事業 今週」「三重県 発表 <今月>」等）。水増し禁止・見つからなければ無理に作らない。

# Step 2: テーマ選定（1本＋予備見出し2本）

1. 全素材から候補を挙げ、次のスコアで選定する: **鮮度（3日以内のニュース・投げ込みは加点）× 亀山接地の新しさ × 草川文脈（アーカイブ接地できるか）− 反復ペナルティ（テーマ履歴14日以内と同テーマ/同切り口は原則除外）**。同点なら新顔優先。
2. 優先順位: **①草川の投げ込み由来（深夜分含む・タグ不問）＞②当日ニュースのSNS向き＞③💡ストック＞④アーカイブ定番（最終フォールバック・使用時は納品DMに「（在庫由来）」と正直に明記）**。
3. **新風枠の義務**: 本命テーマまたは予備見出しのうち**必ず1本**は「直近3日以内のホット話題×亀山ならこうできる」型にする。当日素材が全滅の日のみ免除（その旨を納品DMに1行明記）。
4. 予備見出し2本を選ぶ（本命と別テーマ・クールダウン適用・「Bで」「Cで」の差し替え先）。

# Step 3: 一次調査（薄い投稿の構造的禁止）

1. **ニュース由来テーマは見出しだけで書かない**: 一次記事・公式発表をWebFetchで本文まで読み、数字・固有名詞・日付を取得してから書く。WebFetchがPDFを読めない場合は諦めて記事本文のみで構成（数字の創作は絶対禁止）。
2. **iJAMP由来テーマは必ず公開一次情報に乗り換える**: 省庁・自治体の公式発表をWebSearch/WebFetchで探して裏取りし、**公開情報を出典として**書く。裏が取れなければそのテーマは採用しない。出典言及は「時事通信社の報道によると」以内に留め、iJAMP原文の表現は使わない。
3. **アーカイブ接地（必須）**: `grep -rl "<キーワード>" ~/.claude/agents/knowledge/kusagawa_archive/{01_council,02_publications,03_themes,05_resources,06_election}` → 該当ファイルを `grep -n -C2` で読み、草川の過去発言を最低1件確認（見つからなければ「未発言=新規論点」として扱い、断定を避ける）。
4. 裏が取れない数字・時期には触れない。「確認中」「〜とされています」で逃げず、確実な事実だけで組む。

# Step 4: 生成（短文セット）

📮候補パックの「生成ガイド」節（voice-dnaコア・禁止表現・PF別体裁）に厳密準拠。事実の創作禁止。絵文字なし。他議員名なし。

- **X**: 140字目安・断定短文
- **Threads**: 300〜500字・フック1文→数字1点→草川の見方→議会CTA
- **Facebook**: 500〜800字・文脈→事実→主張→CTA
- **Instagram（写真がある日のみ）**: 600〜1000字・物語型・ハッシュタグ3〜5個。対象写真を `download` で保存し**必ずReadで中身を確認**してからキャプションを書く（写真の内容と食い違うキャプション禁止）。どの写真を使うかをDMで明示する。
- ブログは毎日便では生成しない（「ブログ化」返信時のみ・返信便の管轄）。

# Step 5: 安全ゲート（生成後・送信前に必ず・skip禁止）

1. **fact自己チェック**: 本文中の全ての数字・固有名詞・日付・制度名について出典（Step 3で確認した一次情報 or アーカイブ）を1つずつ照合。出典の無いものは削るか書き直す。
2. **リスク8軸チェック**: 生成ガイドのリスク8軸要点（公選法・個人情報・名誉毀損・差別・利益相反・品位・物議・機密）と禁止表現リストで全文を検査。
   - HIGH該当 → 本文の代わりに「⚠️本日の原稿は〈理由〉のリスクがあります。出してよければ『承知で』と返信を」を納品（原稿はDB保存まで済ませ、承諾後に返信便がDMへ出す）。
   - CRITICAL該当 → そのテーマを破棄し予備テーマで再生成。全滅なら「🚨本日の朝便は〈理由〉により納品を見送りました」を送る。

# Step 6: DM納品（**Notion保存より先に実行**＝Notion障害時も納品だけは死なない）

連投形式（コピペしやすさ最優先・各通は本文のみで余計な前置きなし・1通1900字以内）:

1. 1通目ヘッダ: 「📮【朝便】本日の原稿: 〈テーマ見出し〉（由来: 投げ込み7/22「〇〇」／当日ニュース／新風枠 等）」＋写真がある場合「Instaは HH:MM の写真〈内容1行〉を使ってください」
2. 【X】1通 → 【Threads】1通 → 【Facebook】1通 →（写真日のみ【Instagram】1通）
3. 最終通: 「予備: B.〈見出し〉／C.〈見出し〉 → 修正は『〇〇直して』、差し替えは『Bで』、深掘りは『ブログ化』、動画は『動画で』、今日は見送りなら『パス』」
4. ヘッダ送信のmsg_idで `~/.claude/scripts/sns-routine/_delivery_state.json` に `{"leg":"morning","date":"YYYY-MM-DD","delivery_msg_id":"<msg_id>"}` をWrite（返信便のゼロコストガード用）。

# Step 7: 保存・記録（DM納品後）

1. **📣投稿管理DB**に1ページ作成: 投稿タイトル=テーマ見出し・ステータス=未着手・プラットフォーム=[X,Threads,Facebook(,Instagram)]・ネタ元=由来に応じて 日次活動orSNS/新聞・本文=PF別セクション＋予備見出し。
2. **drafts保存（D1）**: 全PF本文＋予備見出しを `~/.claude/projects/-Users-kusakawatakuya/drafts/YYYY-MM-DD_朝便_〈テーマ短名〉_v1.md` にWrite。
3. **テーマ履歴追記**: `_theme_history.json` に `{"date":"YYYY-MM-DD","leg":"morning","theme":"〈見出し〉","domain":"〈政策ドメインor活動報告〉","source":"投げ込み/ニュース/新風/ストック/在庫"}` を追記（14日超の行は削除）。ステータスページ「テーマ履歴ミラー」節にも同内容を1行追記（14日超の行は削除）。
4. **投げ込み由来の場合**: 📮投げ込み台帳DB（data_source `7a444c29-`）を notion-search（query=投げ込み内容の要点、またはmsg_id）で探し、該当行の「SNS採用」を __YES__ に更新（見つからなければ省略可）。
5. **ステータスページ**: 「本日の納品」節を全置換（便名・送信時刻・納品msg_id・テーマ・由来・予備見出し・接地情報）。「履歴（直近7日）」節に「朝便納品〈テーマ〉」を1行追記。
6. Notionが不通の場合: 1〜5のNotion分は `~/.claude/scripts/sns-routine/_notion_queue.jsonl` に `{"date":"...","type":"sns_delivery","content":"<保存内容の要約とdraftsパス>","dest":"📣投稿管理DB"}` を追記して翌朝ohayoに委ねる（drafts保存とテーマ履歴はローカルなので必ず実行）。
7. **queueフラッシュ**: Notionが使えるなら `_notion_queue.jsonl` を確認し、type=sns_delivery / sns_pack_* の行を保存先に反映して該当行を削除（他typeの行はohayo管轄なので触らない。draftsパスから原稿を読んで📣DBに保存）。

# 返信文法（Step 0の繰越処理用・返信便と同一）

- 「Bで」「Cで」→ 予備見出しへ差し替え、Step 3〜7をフル実行して再納品
- 「〇〇直して」「〇〇風に」→ 指示を反映して該当部分を修正し再納品（修正版は📣DBの同ページを更新）
- 「ブログ化」→ 当日テーマのブログ（800〜1500字・1行目「こんにちは、亀山市議会議員の草川たくやです。」・タイトル50字以内・定型フッター=`~/.claude/agents/blog-writer-normal.md`の「（必須）定型フッター」節を一字一句コピー）を生成し分割DM納品＋📣DBページ先頭にブログ節追加＋drafts保存
- 「動画で」→ 35〜45秒台本（冒頭名乗り→課題→事実1つ→決意型結び・一文30字以内）＋撮影メモをDM1通→ステータスページ「動画リクエスト」節に `- [ ] YYYY-MM-DD 便名 テーマ` を追記
- 「パス」→ 履歴に「パス」記録のみ
- 「承知で」→ HIGH保留中の原稿をDMへ納品
- 「別テーマ: 〇〇」→ そのテーマでStep 3〜7をフル実行
- 解釈不能 → 短く聞き返すDM1通（処理済みに含めない）
- 処理した返信のmsg_idを「処理済み返信msg_id」節に追記（7日超の行は削除）

# エラー時
- **Notion不通**: 納品は中止しない。ローカル素材（テーマ履歴・アーカイブgrep・WebSearch・Gmail・Discord受信）だけで生成し、DM納品→ローカル保存→queue退避で完走する。
- **Discord不通**: 納品不能。可能ならステータスページ履歴節に「🚨朝納品便エラー: 要約」を追記して終了（原稿を📣DBとdraftsに保存できていれば保存し、翌便が繰越納品する）。
- 例外で落ちてよい。原本はDiscordと各DBに保全されているため損失はない。
