内部運用レコード（Discord夜間triageのNotion書き込み本文、📮投げ込み台帳、📝市民意見リストの受付メモ等）をゲートするときは、外形的な数値・固有名詞だけでなく **「〜へ登録した」「〜へ退避した」という実行済みの動作主張** を検証対象に含める。外部から検算できるものは実査する：

- Todoist登録の主張 → `python3 /Users/kusakawatakuya/.claude/scripts/todoist/td.py list | grep -E "<キーワード>"`
- ラベルの実在 → 同 list から `@` 抽出（実在例: @役所 @机上 @夜電話 @結果待ち @現地 @要期限 @保留）
- Notion登録の主張 → 当該DBを引く（本文自身が実行する書き込みは自己言及なので、未来形/予定形が正）

**Why:** 2026-08-14 の triage本文（`_triage_body_2026-08-14_メモ.md`）で、③阿野田のかき氷機・②⑥道野の枯れ木の2件が「Todoistへ期限なし＋@要期限で登録した」と過去形で書かれていたが、td.py実査ではどちらも存在しなかった。台帳に「登録済み」と残ると回収漏れが検知できなくなり、市民案件（倒木＝安全案件）が宙に浮く。

**How to apply:** 実査で裏が取れなければ INCORRECT 扱いにし、「登録する（未実施）」または「登録予定」への書き換えを求めるか、書き込み前に実登録を先に済ませるよう返す。あわせて、原文に存在しない属性の後付け（「現場関係者からの聞き取り」「発言者は伏せ字」など、投げ込み原文に話者情報が無いのに付与された記述）も同時に潰す。伏せ字はイニシャル（三谷→Mさん）だと地区名との組合せで再特定余地が残るため、`◯◯さん`／相談ID等の非導出プレースホルダを推奨する。
