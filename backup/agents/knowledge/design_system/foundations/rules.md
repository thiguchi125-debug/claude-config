## 1. 禁止意匠

- **絵文字禁止**（発信物・印刷物HTML全般。AI臭の筆頭）。見出し装飾は CSSライムバー／角マーカー／罫線で。制作後にコードポイント検査（絵文字混入チェック）を行う。
- **AI製SaaS LP風の意匠禁止**：紫グラデ／浮き角丸カード（drop-shadow浮遊カード）／絵文字丸アイコン／ピルバッジ／LP構図（hero→3カラム特徴→CTA）。
  - 基調（配色・書体・構図）は**内容毎に作り分ける**。特定スタイルの標準化はしない。禁止はあくまで「AI臭」だけ。
  - NGアセットの追加例：ぼかしブロブ背景／絵文字を丸に入れたアイコン（📅📍🎒等）／角丸999pxのeyebrowバッジ／広告コピー然とした中身の薄い抽象キャッチ。良い見本の一例（コピペ標準にはしない）＝`drafts/2026-06_lavender/flyer.html`（クリーム紙＋細い二重インク枠＋ボタニカル線画＋明朝＋手描き風下線＋白フチ写真）。2026-06-11 ラベンダーチラシで確定
- **明るいイラストチラシ（親子・子ども・地域イベント）はHTML手組みで再現しない**：三寺コスモス（2026-07-05）と水鉄砲バトル（2026-07-10）で十数回作り直しても「暗い・硬い・素人以下」で却下され、草川がChatGPTで完成画像を自作して決着。この系統は①ChatGPT/Geminiで完成ポスター画像を生成（プロンプトは用意可）→②こちらの役割は文字校正（電話・日付・会場の化け検出）＋本物QR合成＋A4入稿PDF化＋公選法・事実チェック＋正規保存に徹する。AI画像を参照にHTMLで模写する案も草川は望まない。HTMLゼロ組みは硬めの情報系（議案分析・報告レポート・署名等）に限定
  - 草川が完成デザイン画像を持ち込んだら全面再現を狙わず機能要素（QR・誤字・数字）だけ直す。AI生成QRは飾りで読めない→PILで白箱／暗モジュールのbboxを検出→`qrcode`（誤り訂正H・ブランド色・白地に馴染ませ）で生成→LANCZOS縮小→同中心にpaste→`cv2.QRCodeDetector`でデコード検証してから納品。案件フォルダ＝`~/publications/<案件>/`
  - HTMLで作る場合の理想形は淡色ベース（白／淡色／空色）＋パステル＋水彩やキャラ＋たっぷりの余白。濃色ベタブロック多用を避け、硬さが出たら配色・余白・イラスト量から作り直す（`foundations/styles/style_bright_illustration.html`）
- 架空エピソード・つくり話・情緒メタファー禁止。実体験・一次情報・公式データのみ。
- 他議員の氏名は対外配布物に載せない（内部資料はOK）。

## 1.5 造形の採用則（2026-08-25 追加・参照13点の採寸から）

禁止則（1章）は事故を防ぐだけで、造形の強さを作らない。**全国広報コンクール入選紙面10点＋洋物3点を採寸した結果、
草川の紙面に構造的に欠けていた3点**。対外配布物では以下を最低ラインとして満たす。

### (1) 写真を矩形で切らない — 1面につき最低1か所

採寸した13点は**すべて**角版以外の処理を持っていた。草川版は「矩形写真を枠に置くだけ」で、
これが素人紙面との最短の差になっている。素材ゼロで今日から効く2手:

- **円形マスク＋円の重ね**（tri10・rep01・rep02）— 写真を円で抜き、半透明の大円を重ねる
- **片側フェード**（tri12・tri11）— 写真の片側を `mask-image: linear-gradient()` で地色に溶かす

他に使える語彙: 背景切り抜き＋色面への重ね／大きなR／微傾斜コラージュ（rep09）。

### (2) 数字を図版化する層を持つ — 本文段落に埋めない

rep10 は**写真0枚で紙面の60%を図版が占める**（角丸カード6分割＋特大数字1つ＋ピクトグラム反復＋対比色1か所）。
草川版で写真・図版占有率（Step 4-B ④）が上がらない真因はここ
（三つ折り v2 で④が **7.1%** 止まりだったのと同根）。

- **図表の枠を先に確保してから原稿を流す**。原稿を流した残りに図を入れると必ず入らない
- 「体育館の空調 12か所中0%」「太陽光140件のうちチェック2〜5%」のような持ちネタは、
  段落ではなく**数字ブロック1面**にする（`components/stat_numbers.html`）

### (3) 帯を等幅の水平矩形で終わらせない

参照側は帯を必ず動かしていた。**帯の形を変えるだけで図形語彙が2→4に増える**（実装コストほぼゼロ）:

- (a) **幅違いで階段状に積む**（tri11・tri12）
- (b) **下端を曲線・山形で切る**（rep01・rep02）
- (c) **上下端でフルブリードさせ、表裏の同じ位置で回す**（rep07・rep08・tri12）

草川版の「ベタ帯＋水平罫線」だけの状態で完成にしない。

### (4) 質感は「地紋の代わり」であって装飾ではない

> (4)(5) は参照採寸ではなく、**草川の既存実装に散っていた語彙を規則化したもの**（2026-08-25 追加）。
> 素材と実装は前からあったが、いつ使うかの判断が無く毎回その場判断になっていた。

乗せてよいのは「**面が空いて見えるが、足せる情報が無い**」ときだけ。情報を足せるなら質感より情報が勝つ。

- **家庭用プリンタ配布物には乗せない** — インクを食い、にじむ（インク節約パレットと同じ理由）
- **文字の下に敷かない** — 「背景が汚くて読めない」の主因。どうしても重ねるなら**半透明の濃緑帯を1枚**挟む
- **1面につき1種類**。2種類混ぜた時点で紙面が汚れる
- 使える質感と正本:

| 質感 | 正本 | 効く様式 |
|---|---|---|
| 和紙テクスチャ | `assets/illustrations/washi_texture_01` ＋ `background-blend-mode:multiply` で薄く | `style_washu_calm` |
| 紙目グレイン | `templates/leaflet_trifold` の `.grain`（multiply オーバーレイ） | `style_photo_bold`・本刷りの `style_newspaper_editorial` |
| リソのハーフトーン・版ズレ | `references/a4_flyer/fly01`（かすれ・粒状ノイズ・版の重なり） | `style_bright_illustration` |
| 45°ハッチ | `components/diagram_parts.html` — **分類を色でなく質感で分ける**（印刷での正当な用途） | 図版全般 |

- **破れ紙テクスチャは使わない**（tri11・tri12 由来）。日本の政治広報では古く見える → **生成り #f3efe4 のベタ面**に置換
- 乗せたら必ず Chrome 実測PNGで確認する。画面のプレビューで「いい感じ」は当てにならない

### (5) 躍動は角度で作る — ただし1面1角度

傾きは草川の紙面の identity になっている（斜め緑マッシブ・ライムの色面・ポップ体の揺らし）が、
角度が実装ごとにバラバラで、**規則ではなく手癖**になっていた。以下を正本とする。

| 角度 | 用途 | 実装の正本 |
|---|---|---|
| **-14deg** | 主役級の斜め色面（斜め緑マッシブ） | `templates/leaflet_trifold`（#1f5a3a 塊＋#0f3d27 インセット枠） |
| **±8deg** | 背景の色面・ウェッジ | `digital_templates/instagram_4x5`（ライム面）・`templates/flyer_a4` |
| **±2deg** | ポップ体の1文字揺らし・小要素の微揺らし | `templates/poster`（odd/even で ±2deg） |
| **-2〜-3.2deg** | 写真・カードの微傾斜 | `digital_templates/instagram_4x5`・`templates/poster_a1`・rep09（微傾斜コラージュ） |

- **1面で使う角度は1種類＋写真の微傾斜まで**。3種類混ぜると事故（統一感が消えて「素人が遊んだ紙面」になる）
- **本文が乗る面は傾けない**。読みが落ちる。傾けるのは色面・写真・単語レベルの文字まで
- **顔と水平線を傾けない**（人物の顔・地平・建物）。傾いて見えるのは背景の色面側であるべき
- **躍動ゼロが正解の様式がある** — `style_gov_formal`（整列が権威を作る）と `style_washu_calm`（傾きは格式を壊す）。
  この2つで角度を使ったら、それは様式の選択を間違えている

## 2. CSS実装の確定パターン

- **lime下線は box-shadow inset 方式**：`box-shadow: inset 0 -0.28em 0 #c7ff4a;`
  linear-gradient のハード・ストップ（`background:linear-gradient(transparent 60%, #c7ff4a 60%)`）は**PDF変換で暗化するため禁止**。
- **切れ字（改行分断）対策は固有名詞だけ個別 `white-space:nowrap`**。汎用CSS（body全体 word-break 等）の変更は禁止。
- 印刷色再現：`-webkit-print-color-adjust: exact; print-color-adjust: exact;` を必ず入れる。
- ブランドカラーは `foundations/colors.html` 参照（ライム #c7ff4a／濃緑 #1f5a3a／最濃緑 #0f3d27／生成り #f3efe4）。家庭用プリンタ配布物はインク節約パレット（#1f7a3a／#0e4d27／#c89211・ベタ塗り3%以下）。
- 日本語はHTML/JSON内でも**直接書く**（unicode escape禁止）。「亀山」のtypo（亜山・亵山）絶対禁止 — JSON escape 由来の事故実績あり。

## 3. 画像・写真処理

- **写真ハードゲート（対外配布物・skip禁止）**:
  1. **実写真を1枚以上入れる**。AI生成写真での代替は禁止（実在感が消え、AI臭の主因になる）
  2. **写真・図版の占有率は参照カルテの数値を下限**として扱う（Step 4-B ④で採点。下回ったら差し戻し）
  3. 実写真が確保できない案件は、写真を薄く小さく入れて誤魔化さず**タイポグラフィを絵にする路線へ切り替える**（参照 brand01 / 様式 `style_ink_saving_report`）
  4. 例外はプレビュー・テンプレ共有物のみ（人物写真・個人情報を含めないため、プレースホルダー矩形で代替する）

- 画像最適化：`sips -Z 1500 -s formatOptions 90 <img>`（A4で300dpi目安）。
- EXIF：`PIL ImageOps.exif_transpose` で回転正規化＋EXIF strip（位置情報等の漏えい防止）。
- バイナリ素材は案件別サブフォルダ `<YYYY-MM>_<案件名>/` に隔離。中間版は最終確定後に削除。
- 写真は photo-curator（草川 ZPERSON=18）で選定。プレビュー/テンプレ共有物には人物写真・個人情報を含めない（プレースホルダー矩形で代替）。

## 4. レイアウト工程

- レイアウト作り込みは **print-layout-architect** に任せる（画像大きく・text-beside-image 2カラム・Chrome実測反復）。エージェントが0ツールで停止したら自分で実測ループ（scrollHeight−clientHeight=0 確認）。
- `margin-top:auto` でのフッター押し下げ禁止（オーバーフロー事故源）。横長地図は `aspect-ratio` ＋ `object-fit:cover`。
- 物理破綻チェックは **natural-design-reviewer**（写真切れ・枠外はみ出し・大空欄・連絡先切れ。2回目以降は新規指摘のみ）。
- 勝負所（選挙物・大判ポスター）のみ design-director で8軸昇格（草川承認制）。

## 5. PDF生成・入稿

- PDF生成コマンド例：
  ```bash
  "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
    --headless --disable-gpu --print-to-pdf=<絶対パス>.pdf --no-pdf-header-footer <絶対パス>.html
  ```
- **PDF生成後は `open <絶対パス>` を即実行**（草川が目視できる状態にする）。HTMLは自動openしない。
- **ラクスル入稿の裏面ラスタライズ**：フォント・エフェクト起因の入稿エラーは裏面を `pdftoppm -r 400` ＋ PIL でJPEG化→表面PDFと再結合して回避。
- 政治活動印刷物には**「討議資料」表記**を必ず入れる（公職選挙法対策。リーフレットv3 の `.f-discussion-mark` 参照）。

## 6. 印刷物チェックリスト（配布前・回収不能）

1. **レイアウト**：余白実測（上下差2mm以内）／はみ出し・切れゼロ／ページ配分に意図がある
2. **タイポ**：切れ字nowrap／ウェイト4段／本文line-height 1.7以上／固有名詞コピペ（手打ち禁止）
3. **写真**：300dpi相当／EXIF処理済／構図破綻なし／キャプション・出典
4. **章順・構成**：情報階層が3秒で読める／数字は一次資料照合済み
5. **安全ゲート**：content-fact-checker → content-risk-reviewer 通過（対外配布物は必須・skip禁止）
6. **俯瞰レビュー**：最終PDFを1枚絵として引きで見る（EYES-FIRST）／「討議資料」表記／他議員氏名なし／絵文字なし
