画像実装の機械ゲート2本には、実装のしかたを縛る非自明な仕様がある。設計段階から織り込む。

**1. `check_overflow.py` は「絶対配置の兄弟どうしの矩形交差」を無条件に重なり違反にする**
斜めのライン・地紋・グラデ膜など、`clip-path` で形を作る装飾レイヤーを `position:absolute; inset:0` の兄弟として置くと、
`getBoundingClientRect()` は clip-path 前の全面矩形を返すため、文字ブロックと必ず交差して 🚨 になる。
- **Why:** 判定は矩形ベースで、clip-path / mask を解釈しない。
- **How to apply:** 装飾レイヤーは **親の擬似要素（`::after`）で描く**。`querySelectorAll('body *')` に載らないので判定対象外になる。
  文字ブロック側は装飾の**子孫**に入れておくと `contains()` で除外される（親子は重なり判定をスキップする実装）。

**2. `feed_preview.py` の「空きポケット」は安全域（1600×900なら x400〜1200）の内側しか見ない**
左右各400pxの捨て代は規格上の空白として除外される。つまり **x400より左に置いた要素は「実体なし」扱い**になり、
その行は空セルとして数えられて大余白（≥10%で不合格）に化ける。
- **Why:** 1:1クロップで消える帯を毎回⚠にしないための除外（2026-09-04の改修）。副作用として左端寄せの署名・氏名カードが無視される。
- **How to apply:** T5（斜め片側色面）のように文字を左の色面に寄せる型では、**下段の氏名カードに幅を与えて x400 を跨がせる**（例：width:612px の銘板にして役職左・氏名右の space-between）。
  縦の詰め直しだけでは消えない。実測ではカードを x88〜330 から x88〜700 に広げただけで 17% → 9% に落ちた。
- ついでに：閾値は **10%**。写真側の平坦部（頬・空）も空セルとして拾うので、9%前後で最大ポケットが写真側に移ったらそれ以上は詰めなくてよい。
