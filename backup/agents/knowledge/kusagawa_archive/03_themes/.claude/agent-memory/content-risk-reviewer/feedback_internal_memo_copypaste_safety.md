内部保管が目的の文書（🎯政策・質問ネタDB、調査メモ、質疑設計書など）をレビューするとき、
判定基準は「草川本人が読む時点の安全性」ではなく **「後日ここから議会質問原稿・ブログ・SNSにコピペされる時点の安全性」** に置く。

**Why:** 草川の運用では、ネタDBカードは一般質問原稿・ブログの一次素材として後日コピペされる前提で書かれている。
内部戦術メモ特有の表現（「逃げ答弁を封じる」「言い訳を潰す」「〜では答えにならない」、
市がまだ言っていない答弁を鍵括弧で市に帰属させる書き方）は、内部では正当な準備だが、
そのまま対外に流出すると Axis 4（名誉毀損・予断による事実摘示）／Axis 7（品位・市職員敵視）に転化する。
2026-08-25「きょうだい居場所」カードのレビューで、この転化経路が唯一の HIGH 要因だった。

**How to apply:**
- 内部文書のリスクは「削除」ではなく **隔離** で解く。内部戦術行は残す価値があるので消さない。
- 冒頭に凡例を置き、戦術行の先頭に `【内部メモ】`（テキストマーカー。コピペで消えない。
  bill-scrutiny-scriptwriter の 🔒 と同義だが、発信物の絵文字禁止ルールとも衝突しない）を付ける。
- 各戦術行には **対外流用時の言い換え具体文** を1本併記する。抽象的な注意喚起では事故は防げない。
- 特に危険な形式：**市がまだ答弁していない内容を鍵括弧で市の発言のように書く**。
  対外に出ると「市がそう言った」と読まれ、虚偽の事実摘示になる。「想定される市の説明が〜に集約された場合」と条件形に直す。
- 文書末尾の「使用前に fact-checker → risk-reviewer を通す」注記だけでは不十分。
  コピペする人は末尾まで読まないので、危険な行そのものにマーカーを付ける。
