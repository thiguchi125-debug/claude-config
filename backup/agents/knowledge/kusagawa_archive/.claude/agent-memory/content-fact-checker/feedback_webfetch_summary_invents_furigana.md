WebFetchの返り値に「櫻井楽都（さくらい らくと）」のような**原文に存在しない情報**が混ざることがある。要約を担当する小型モデルが文脈から補完してしまうため。

**Why:** 2026-09-04の櫻井楽都選手ファクトチェックで実際に発生。月刊陸上競技・伊勢新聞の両記事をWebFetchすると要約が「（さくらい らくと）」と返したが、`curl`＋タグ除去で原文を直取りすると**両記事ともふりがなを一切載せていなかった**。一方、全中公式速報PDFの氏名カナ欄は `ｻｸﾗｲ ｶﾞｸﾄ`。要約を信じていたら中学生の名前の読みを誤って発信するところだった。

**How to apply:**
- 人名の読み・氏名の漢字・所属・数値の桁は、WebFetch要約で「確認できた」としない。以下のどちらかで原文を必ず突合する。
  - `curl -sL -A "Mozilla/5.0" <URL>` → Pythonで `<script>/<style>` 除去＋タグ除去 → 対象語の前後をgrep（`re.finditer(r'.{0,80}櫻井.{0,120}')` 等）
  - PDFは `pdftotext -layout`（大会速報・議事録・統計はここが最強の一次情報。氏名カナ欄まで入っている）
- 「複数の報道が同じ読みを書いている」とWebFetch要約が言う場合ほど危険。**同じ要約モデルが同じ推測をしているだけ**のことがある。
- 判定は「一次情報の原文にその文字列が存在したか」の二値で行い、存在しなければ VERIFIED にしない。
