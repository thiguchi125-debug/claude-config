`01_council/` の令和8年3月定例会 会議録txtは、**ファイル名と中身が1日ずれて入れ替わっている**。

| ファイル名 | 実際の中身 |
|---|---|
| `mydrive_亀山市定例会第2号_令和8年3月4日_tcuP0.txt` | **議事日程（第3号）令和8年3月5日（木）** = 議案第33号基本構想・第34号前期基本計画に対する質疑（草川の「乗って残す」質疑はここ） |
| `mydrive_亀山市定例会第3号_令和8年3月5日_HJfY2K.txt` | **議事日程（第2号）令和8年3月4日（水）** = 令和8年度施政及び予算編成方針に対する代表質問 |

裏付け：第3号側の末尾が「明日６日は午後１時から会議を開き」で締められており、3月5日の議事であることが内部整合。3月4日(水)・3月5日(木)の曜日も一致。

**Why:** 2026-08-10 の朝便SNSファクトチェックで、原稿が「令和8年3月4日 議案質疑」と書いていたのはこのファイル名を信じたため。実際は令和8年3月5日。議員発信物で議会発言の日付を1日ずらすと、会議録と突き合わせた市民・他会派に即座に指摘される。

**How to apply:** `01_council/` の会議録txtを引用するときは、**ファイル名の日付を使わず、必ず中身の冒頭「●議事日程（第N号）令和X年Y月Z日」を読んで日付を確定**する。これらのファイルはJSON1行・`fileContent`キーなので `python3 -c "import json;print(json.load(open(f))['fileContent'][:300])"` で冒頭を確認するのが最短。他の会期のファイルにも同種のずれがある可能性があるため、日付を引用する全ケースで冒頭確認を習慣化する。
