自治体サイトの記事の**更新日は「追記した日」であって「その制度・サービスが始まった日」ではない**。更新日を開始日の根拠に流用すると、1ページに並んでいる複数の仕組みの開始時期を1つに合成してしまう。

2026-08-24 朝便で実際に起きた：亀山市「ツキノワグマの出没状況および注意喚起について」の更新日 2025-11-18 を根拠に「クマも昨年11月からマップとアプリで見られる」と3PF全てに書いた。正しくは **出没情報マップ＝令和6年6月7日から／スマホアプリ「けものおと2」＝令和7年11月13日から**で、マップは1年5か月ズレていた。市ページの docs ID が `2024060600015`（＝2024年6月6日作成）である時点で、更新日より前から存在していたと分かる。

**Why:** 更新日は「いつから使えるか」を答えない。二次ページの日付で一次の開始時期を代用した瞬間、相対年表現（「昨年11月から」）が事実の主張に化ける。[[feedback-relative-year-drift]] の1年ズレと同じ系統で、こちらは**複数の開始時期を1つに潰す「合成エラー」**という別の壊れ方をする。

**How to apply:**
- 「〇〇年〇月から使えるようになった」と書くときは、**提供している主体（県・国・市）の報道発表や制度ページ**まで遡って開始日を取る。案内している側のページの更新日で代用しない。
- 1ページに複数の仕組み（マップとアプリ、旧制度と新制度）が並んでいたら、**それぞれ別の開始日を持つと仮定して**個別に裏を取る。
- docs ID・URL の数字列が作成日を含むことが多い（亀山市 `docs/2024060600015` = 2024-06-06）。更新日との差が大きければ、その差の間に何が追記されたかを疑う。
