制作案件のフォルダ（`~/publications/<案件>/` `~/outputs/<案件>/`）は、**番号付きの固定構成＋案件ルートに `README.md`** で組む。作業の途中で生まれた中間ファイルをフォルダ直下に置きっぱなしにしない。

```
01_最新PDF/        完成品はここだけ・常に最新1本
02_原稿/           本文原稿・入稿指示書
03_デザイン参照/     参照画像＋sources.txt（出典）
assets/            素材本体（HTMLからの相対パスがあるので名前は変えない）
  📥ここに新しい写真を入れる/   草川が写真を置く口。用途別にサブフォルダを切る
99_過去バージョン/   旧HTML・旧レンダリング・旧PDF・修正メモ
README.md          構成表／決めごと／現在の状態／待ちになっているもの
```

**Why:** 2026-08-13 草川指摘「フォルダの中も分かりにくいので分かりやすく」。三つ折りレポートの案件フォルダが、HTML7本・renderディレクトリ5個・PDF3本・fixes_v2〜v4.md が直下に並ぶ状態になっていて、どれが最新か本人が判別できなかった。制作は版を重ねるほど中間物が増えるので、**放置すると必ずこうなる**。番号を振ると Finder の名前順がそのまま作業順になる。

**How to apply:**
- 版を切ったら**その場で**旧版を `99_過去バージョン/` へ落とす。あとでまとめて片付けない。
- **`assets/` はリネームしない**（HTML/CSSの相対パスが壊れる）。整理は直下の散らかりから先に潰す。
- 写真を草川に依頼するときは、受け取り口のフォルダを**先に作って `open` してから**依頼する。用途別にサブフォルダを切る（例 `熊本地震_救援物資/` `三寺コスモス畑/`）。
- `README.md` には構成表だけでなく **「現在の状態」と「待ちになっているもの」** を書く。セッションをまたいだとき、ここを読めば再開できる状態にしておく。
- 最新成果物の開き方は [[feedback_open_folder_after_generating_files]]（`show_latest.sh`）に従う。
- 保存先そのものは [[reference_storage_map]] の正規置き場に従う。
