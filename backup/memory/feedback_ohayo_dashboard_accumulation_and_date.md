2026-05-31 に朝のダッシュボード(722beb9e...)で重大事故2件が同時発生。草川から「ダッシュボードがめちゃくちゃ／なぜ」「今日は5/31だが」と指摘され発覚。

## 何が起きたか
- **事故① 本文堆積**: 📅今日のスケジュール・🎯今日のフォーカスの更新で、`update_content` の old_str に「見出し1行だけ」を入れ、new_str に「見出し＋当日本文」を入れていた。→ 前日までの本文が消えず、新しい日の本文が上に積み増しされ続けた。結果 5/26〜5/31 の約6日分の動線箇条書きが1セクションに混在。過去の置換失敗で `\</old-removed-2\>` という編集タグ残骸も本文に残留していた。
- **事故② 日付誤認**: 同一カレンダー日に「おやすみ」(5/31処理)→直後「おはよう」が来た際、当日を翌日6/1と誤認。スケジュール・選挙カウントダウン(146日/139日=6/1値)・各見出しに6/1を書き込んだ。正しくは5/31(147日/140日)。

## なぜ起きたか
- lean/v2.5の「燃費節約のため見出しの日付だけ更新・本文置換は省略」を、フォーカス/スケジュール/タスクにまで適用してしまった。これらは「本文ごと全置換」が前提のセクションなのに、見出し置換だけにしたため堆積した。
- 当日日付を `date` で実確認せず、直前ターンの「明日」を引きずった。

## How to apply（毎朝必ず）
1. **日付は最初に `date +%Y-%m-%d` で実確認**し currentDate と照合。直前oyasumiの「明日」を当日と取り違えない。
2. **📅スケジュール・🎯フォーカス・✅今日のタスクは「見出し＋本文を含むセクション全体」を1 old_str に入れて全置換**。見出し1行だけの置換は禁止（堆積の原因）。前日本文を必ず old_str に含めて消す。
3. 更新後 verify で「同種見出し2つ以上／1本軸2つ以上／前日以前の日付残存／`</old-...>`タグ残骸」を検出したら即 `replace_content` でセクション再構築。
4. 既に堆積が起きている場合は部分置換に固執せず **replace_content でページ全体をクリーン再構築**（子ページは `<page url="...">` で new_str に必ず含めて保持＝replace_contentは子削除時エラーで安全停止する）。
