## C. 標準ワークフロー（NotebookLM経由）

### C-1. 受領時のヒアリング項目

1. **自治会名**：地区別ニュース既存ファイルの有無を確認
2. **想定聴衆**：年齢層・人数・政治的関心度
3. **会場・時間**：プロジェクター有無・想定発表時間
4. **主要テーマの希望**（市から決まっている場合）
5. **特記事項**：地元要望・最近の困りごと・前回市政報告会からの間隔

### C-2. アーカイブgrepの優先順位

```bash
# 1. 地区固有ニュースの存在確認（最優先）
ls ~/.claude/agents/knowledge/kusagawa_archive/02_publications/{reports,leaflets}/ | grep -iE "<地区名>"

# 2. 地区名・道路名・小学校名で grep
grep -rl "<地区名>" ~/.claude/agents/knowledge/kusagawa_archive/{01_council,02_publications,03_themes,05_resources,06_election}/

# 3. 草川独自表現での grep（voice-dna整合）
grep -rl -E "乗って残す|予防型|届ける仕事|一生応援" ~/.claude/agents/knowledge/kusagawa_archive/

# 4. テーマ別 03_themes/ 確認
cat ~/.claude/agents/knowledge/kusagawa_archive/03_themes/<テーマ>.md
```

### C-3. ソース束作成の構造

```
# v2型統合ソース束 構造
- メタ情報（作成日・用途・抽出ルール）
- スライドごとに「出典1〜N」で章立て
- 各出典は「草川質問×市答弁ペア」「市公式資料」「草川自身の発信物」のいずれかを明示
- 他議員質問への市答弁は「議会の質疑で確認」と汎用表記
- 補足資料（voice-dna・楠平尾町地理）
- 出典管理メモ（NotebookLM出力後の必須チェック）
```

### C-4. プロンプト作成の構造（8セクション）

1. **聴衆プロファイル**（地区・年齢層・関心テーマ・過去経緯）
2. **講演者プロファイル**（草川スタイル）
3. **出力スライド構成**（厳守8枚 or 任意枚数）
4. **各スライドの構成テンプレート**（タイトル・現状課題・対策・楠平尾文脈・スピーカーノート・データ出典）
5. **必ず使用する数字・固有名詞**（スライドごとに列挙）
6. **トーン指針**（冒頭挨拶・キーフレーズ・専門用語括弧併記）
7. **厳守事項**（他議員氏名禁止・公選法配慮・架空エピソード禁止）
8. **草川発言と他議員引き出し情報の区別ガイド**

### C-5. 出力後の必須チェック

1. NotebookLM出力をユーザーが受領
2. **content-fact-checker** で数字・固有名詞・年次照合
3. **content-risk-reviewer** で公選法・名誉毀損・品位8軸スキャン
4. 他議員氏名残存の最終grep確認（`grep -nE "森美和子|森議員|古田議員..."`）
5. PowerPoint/Canva/Marpへ展開（ユーザー側作業）

### D-4. 禁止表現チェックリスト

- ❌ 投票日・期数・「もう一度」を強調する選挙寄り表現
- ❌ 「次の議会で追及」型の特定議会×対決動詞の組合せ
- ❌ 架空エピソード・つくり話（「ある中学生が泣いた」型）
- ❌ 個人情報（市民の個人名・住所等）
- ❌ 特定の対立候補・他議員批判
