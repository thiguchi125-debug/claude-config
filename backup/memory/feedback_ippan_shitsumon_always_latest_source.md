一般質問は通告後も議場直前まで検討が続き、**通告書も想定質問も版が増え続ける**。作業に入る前に必ず最新版を取り直す。ローカル `drafts/` のファイルは古い版が残り続けるので、**ファイル名の日付だけを根拠にしない**。

**Why:** 2026-09-02、市民のSNS投稿へのコメント作成で事故った。`drafts/2026-09-01_一般質問通告書_提出用_8kenmei版.txt`（8件名）を最新と誤認し、「産科・周産期の件名は通告に無い」「通告締切が過ぎているので9月議会では取り上げられない」と草川に**誤った指摘**をした。実際の提出版は6件名11小項目で、**件名3「周産期医療の体制について」は入っていた**。草川の「来週の議会で取り上げる」は最初から正しく、こちらが古い叩き台を見て止めにかかった形。同じ `drafts/` に v1/v2/叩き台v2〜v4/8kenmei版 が同居し、どれも同じ日付を持っていたのが原因。

**How to apply:**
- **通告書の正本＝受付印付きの提出版**（Drive の `一般質問通告R8.9月.pdf` 形式）。`mcp__claude_ai_Google_Drive__read_file_content` で読む。件名数・小項目文言・答弁を求める者・所要時間・登壇時刻はここでしか確定しない。
- **想定質問の正本＝Notion「🏛 議会会期ハブ」配下の該当会期ページの最新版**（例: 2026年9月議会 →「🎯 想定質問の流れ v3」）。`page_last_edited_at` を必ず見る。v1/v2は同じ親の下に残置されているので、バージョン番号が最大＝最新とは限らない点に注意（更新日時で判断）。
- `drafts/` の通告・想定質問ファイルは**作業中間物**。読んでよいが、単独で事実の根拠にしない。提出版・Notion最新版と照合してから使う。
- 議場での射程は**提出版の小項目文言**が決める。想定質問メモ側の語（例: 「公示」）が通告に無ければ通告外を指摘されうるので、両者の差分を毎回取る。
- 会期中に議会質問へ言及する発信物を作るときは、**発信の直前にもう一度最新版を取り直す**。特に議場までの日数が残っているほど更新が入る。
- 関連: [[feedback_check_artifacts_before_scheduling_work]]（_status.jsonを信じず実物を見る）／[[feedback_council_schedule_commitments_require_tsuukoku]]（議会回次に紐づく行動を書けるのは提出済み通告に件名があるときだけ ── 本メモにより「提出済み通告」＝受付印付き提出版で確認すること）
