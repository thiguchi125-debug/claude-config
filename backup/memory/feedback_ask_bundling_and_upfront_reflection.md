**確認（AskUserQuestion）は最初に1回だけ束ねる。草川が最初の入力に書いている情報は、最初の版から全部反映する。**（2026-07-31 草川指摘「台本遅いよ、なんで最初から反映しないの」）

**Why:**
2026-07-31の熊本地震 支援物資ショート動画で、確認を3回に分けて挟んだ結果、台本の完成が遅れた。締切が翌日正午という時間制約のある案件で、往復を刻むのは致命的。

具体的に何が悪かったか:
1. **確認を3ラウンドに分けた** — ①名義＋軸 ②安全ゲートの取り込み範囲＋展開面 ③名簿の扱い。②③は①の時点で論点が予見できていた（受入場所が議員個人事務所である以上、名義・呼称・名簿は同じ「名義分離」という1つの塊）。1回で聞けた。
2. **草川の入力にあった数字を最初の版に入れなかった** — 「簡易トイレ20」は最初の投入テキストに書かれていた。単位（個／基／セット）が原資料になかったため「確認できるまで出さない」と判断して全カットから外したが、**それは草川に1問聞けば即座に解決する情報**だった。最初の確認ラウンドに「簡易トイレの単位は？」を1行足すだけでよかった。結果、画像・台本・SNS・Notionの4面に後から伝播させる二度手間になった。
3. **安全ゲートの指摘を「草川に判断を仰ぐ」形で丸投げしすぎた** — fact-checker/risk-reviewerが出した論点のうち、自分で解決できるもの（TELの帰属＝新聞に記載あり／気象庁の命名＝確認済み）まで一緒に並べて出しかけた。自分で潰せるものは潰してから残りだけ聞く。

**How to apply:**
1. **タスク開始時に「この案件で草川にしか答えられないこと」を全部洗い出してから、1回のAskUserQuestionにまとめる。** 途中で新しい論点が出たら、それは最初の洗い出しが甘かったということ。
2. **草川の投入テキストにある数値・固有名詞で、単位や表記が曖昧なものは、その最初の確認に混ぜる。** 「原資料にないから出さない」と勝手に落とさない。落とすと後で全面伝播のやり直しになる。
3. **安全ゲートの指摘は、自分で一次情報に当たれば解けるものを先に解いてから草川に出す。** 「9件指摘がありました」ではなく「9件のうち6件は解決済み、判断が要るのは3件」の形にする。
4. **締切が近い案件（当日・翌日）では、確認は1回まで。** 2回目が必要になった時点で、既定値で進めて「こう決めた、変えたければ言って」の形にする。
