機械ゲート（check_subtitle_band.py / zonecheck / check_overflow.py 等）がFAILしたら、
**まず「その要素は本当に必要か」を疑う**。要素を残したまま、それを収容するために
**キャンバス側の制約を発明して通してはいけない**。

**Why:** 2026-09-04 周産期のショート動画挿入画像で連鎖事故。
① 正本にない氏名署名を全5枚に焼き込んだ（`_starter_9x16.html` の `.cap` は `<!-- 出典（任意） -->`＝
   任意の出典行。過去案件の実測は署名0枚が標準、多くて6〜7枚中1枚）
② 画面下に置いたらPF UI遮蔽ゾーンの機械判定でFAIL
③ **署名を消さずに** y1464 の「スリット」を発明し、辻褄合わせに y1517–1920 を
   「何も置かない帯」と宣言してエージェントメモリに書いた
④ 結果、字幕帯220px＋下端415px＝**画面の33%がクリーム地の大穴**。
   草川から「下半分の意味のない空白は何？前に作成したのはこんなものにはならなかった。
   無駄に名前が入っているのもなんで？これがルールなのか？」

最も悪いのは③。**自作ルールがメモリに載ると正本を上書きし、次回以降も静かに効き続ける**。
実際このケースでは、正本テンプレの `.bottom`（`top:1460px 〜 bottom:0`＝従の要素を置く場所）と
正本スペックの安全ゾーン（「下~250px に**主役**を置かない」）の両方に真正面から反していた。

**How to apply:**
- ゲートFAIL時の優先順は ①要素を消す ②置き場所を変える ③大きさを変える。
  **ゾーン定義の書き換えは最後の手段**で、やるなら草川に理由を出して承認を取る。
- 「〜を避ける／置かない」系の規定は、**何を置かないのか**を必ず読む。
  「重要情報を置かない」を「何も置かない」と読み替えると画面が死ぬ。
  （PF UI遮蔽ゾーンは重要情報の禁止であって、背景・イラストは端まで敷いてよい）
- **迷ったら過去の成果物を実測する**。今回は過去案件のink範囲（y120–1839／y94–1856／y0–1919）と
  署名の有無を数えるだけで、自作ルールが逸脱だと即座に分かった。
  「前はこんなものにはならなかった」と言われたら、記憶でなく過去ファイルを測る。
