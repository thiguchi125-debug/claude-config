2026-05-08 news-briefing で「亀山駅前信号機撤去 市長『遺憾』」「エイチワン亀山新工場180億円」の2件を当日ニュースとしてDBに登録したが、いずれもYahooニュースURLは404。実は2025年初頭の古い記事をキャッシュ経由で誤取り込みしていた。

**Why（罠の正体）:**
1. WebSearch クエリに「2026年5月」と書いても日付フィルタは効かない（Yahoo検索の仕様）
2. Yahooニュースは7日経過で記事本体が消える仕様（404）
3. 検索エンジンキャッシュにはタイトル・URL・スニペットだけ残る → 「最新ニュース」と誤判定するリスク
4. 同じ検索結果群に「亀山市長選 来年1月26日投開票」のように年月の手がかりがあれば、それを基準に時期を逆算できたが、見落とした

**How to apply（再発防止・必須手順）:**
- WebSearch結果からニュースDBへ登録する前に、**必ず WebFetch で記事本体の実在確認＋配信日確認**を行う（SKILL.md規定）
- WebFetch が 404 / 内容スカスカで返ったら**即除外**（拾わない）。SKILL.md に既に明記されているが2026-05-08は完全スキップしていた
- 検索結果群の中に「来年X月」「○年前」「○○期目」等の時期手がかり語があれば、その文脈から発信時期を推定し、48時間以内かを判断
- Yahoo検索の `2026年5月` 等の日付クエリは効かない前提で、別の鮮度シグナル（記事URLの日付パターン、原典サイト直接アクセス、配信時刻メタタグ）を併用
- 過去7日DBクエリで重複排除する際、見出しだけでなく**「過去7日に出てない＝新規」と判定する条件と、原典記事の発信日が当日±2日以内かを別軸でチェック**

**事故記事のステータス:**
- ニュースDB358cf503...8169 と 358cf503...8141 の2件は見出しに【⚠️取り下げ・鮮度未確認】を冠して保留化済み
- 信頼できる残2件: 「南海トラフ被害想定3月精緻化」「国政動向5月の流れ」は出典がpref.mie.lg.jp / cas.go.jp の一次ソースなので維持
