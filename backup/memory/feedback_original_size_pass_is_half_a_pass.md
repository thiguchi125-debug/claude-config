発信ビジュアル（サムネ・OGP・SNS画像・動画の挿入画とカバー）は、**原寸100%で破綻ゼロでも合格の半分でしかない**。読者が見るのは常に縮小されたフィードの中であり、そこで成立しなければ意味がない。確定前に必ず `feed-visual-reviewer` を通す。第一手＝`python3 ~/.claude/scripts/feed_preview.py still|short|telop <対象>`。

**Why:** 2026-08-31、育休退園ブログのサムネで実際に起きた。`visual-assets-playbook.md` A節の作法（Hiragino W9・palt・レンダ→PNG自Read）を全部満たし、原寸1200×630で破綻ゼロだったが、**本文20pxがXカード幅400pxで約7pxになり読めなかった**。作った側は原寸で見るので永久に気づかない。同日、既存のショート動画パッケージ（`2026-08-25_ikukyu-taien`）でも同型の穴が2つ実在した：①挿入画3枚とも**出典表記が下部キャプション帯**、緑ピルラベルが上部ナビ帯に入り本番では隠れる（字幕セーフ帯 y1240〜1460 は正しく空いており既存ゲートは全PASS）②テロップ8行中6行が可読速度を超過（最悪＝1.8秒に36.5字／上限9字）。いずれも既存の検査を全部通過していた。

**How to apply:**
- **原寸を見て判定しない。** 必ず縮小コンタクトシートを見る。これを飛ばした判定は無効
- 静止画の目安＝**400pxで読めない文字は情報量ゼロの装飾**（削るか拡大するかの二択）／メイン1行は原寸100px以上・副1行56px以上／**文字ブロックはサムネ4つまで**／伝える用件を1文で言えなければ図版であってサムネではない
- 9:16は**字幕セーフ帯とPF UI遮蔽ゾーンは別物**。UIが乗るのは 上部y0〜221／右x900〜1080×y900〜1700／下部y1520〜1840／最下部y1843〜。**出典をここに置かない**
- テロップは**発話7字/秒・補助5字/秒**。出典・連絡先・免責は「掲示」で速度判定の対象外
- ゾーン座標は目安。実機スクショで較正するまで暫定であり、閾値を無断で緩めない
