# brainstormingセッションのトークン浪費パターン

設計セッション（brainstorming skill経由）でPhase 1相当の小規模整理タスクなのに、design docを1.5万字書いて同じ内容のmdを4回出力してしまう浪費が発生する。

## 失敗パターン3点
1. **保存先ガイド・手順書を複数ファイルに分散重複生成**
   - design doc 内に全文埋込
   - Drive upload用結合版
   - Drive upload用分割版×2
   → 同一内容を3〜4箇所で繰り返す
2. **design docの章立て肥大化**
   - 12章構成・1.5万字
   - Phase 1の実行に直接必要な情報は3割程度
3. **探索並列の過剰実行**
   - 全フォルダ並列内容確認（実際は1〜2個サンプリングで判定可能）
   - 失敗ツール（権限エラー等）の再試行を1〜2回したあとローカル退避

**Why:** 2026-05-11議会資料管理システム設計セッションで実際に発生。Phase 1（Drive整理＋設計書）だけで100K以上のトークン消費。

**How to apply:**
- design docは「目的達成に直接必要な情報」だけに絞る。Phase分離している場合、Phase 1相当のセクションのみ書く（目標3000字以内）
- 同内容を別ファイル形式で複数生成しない。1ソース→1配置先で済むよう設計
- Drive・Notion等の探索は1〜2個サンプリング→傾向推定→必要に応じて追加探索の段階方式
- MCP書込権限エラー等は1回失敗で別経路（ローカル退避＋手動アクション提示）に切替
- 完了報告は機能区切りせず最小サマリ＋次の一手だけ
