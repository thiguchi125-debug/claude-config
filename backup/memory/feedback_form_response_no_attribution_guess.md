# フォーム回答の属性帰属は operational context で判定する

**ルール**: Googleフォームや申込フォームの自由記述欄で主語が書かれていない属性（アレルギー・体調・配慮事項等）は、**運営文脈から自然な主体を判定して進める**。
- お弁当発注リスク文脈 → 食べる主体（基本：お母さま／大人参加者）のアレルギー
- 離乳食・おやつ持込文脈 → お子さまのアレルギー
- 託児中の食材接触文脈 → 同伴お子さま全員のアレルギー
- どちらの可能性も均等にあり判断できない時だけ、返信本文で1行確認

**Why**:
2026-05-19 「温泉で、産後ケア。」初回申込（なかむらあいり様）対応で、フォーム回答「えびかに」の帰属を：
- **第1誤**: 「お子さまのアレルギー」と機械的に断定（1歳1ヶ月の子が甲殻類を食べる場面は稀、お弁当発注対象は親、にもかかわらず子に帰属させた不自然な推定）
- **第2誤**: その指摘後に「どなたの分か要確認」と過剰是正（運用文脈からは親と判定できる場面なのに、無駄な確認問合せを差し込んだ）
- 草川から「親に決まっている。確認はいらん、お弁当に配慮する文章だけ入れて」と指摘

つまり「推定するな」が答えではなく、「**運営文脈から自然な主体を選んで処理せよ。それでも分からないときだけ確認**」が正しい。お弁当（500円）を食べるのはお母さまなので、フォームの「えびかに」は当然お母さまのアレルギー＝お弁当発注で甲殻類除去で対応、と一発で結論を出すべきだった。

**How to apply**:
1. **第1ステップ：運営文脈で主体を判定する**
   - お弁当・大人用品 → 申込本人（基本お母さま）
   - 子ども用品・離乳食・おもちゃ → お子さま
   - 託児・保健師相談 → お子さま中心、お母さま補助
2. **第2ステップ：判定結果に基づいて即運用対応を組み立てる**
   - アレルギー特定→お弁当発注で該当食材除去
   - 体調配慮→保健師申し送り
   - 「対応します」と返信、無駄な確認問合せは差し込まない
3. **第3ステップ：本当に判断不能な時だけ確認**
   - 複数同伴者がいる、文脈が両方の可能性を均等に持つ場合のみ
   - 「念のため」での過剰確認は信頼を損なう（プロらしさを欠く）
4. **返信での「確認段落」の差し込みは慎重に**
   - 確認するなら本当に必要な1点だけ
   - 「念のため」「気になりまして」型の差し込みは禁止
5. **citizen-inquiry-responder / iken / aisatsu-prep / 申込対応系全般に適用**
