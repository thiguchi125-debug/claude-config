**現状（実測 2026-09-06）**: archive/ 35本・140KB（9/2〜、1日約7本）。handoff_notice.py は24h以内・最大3本しか読まないので固定費は増えない。穴は2つ＝①「終了」を記録する仕組みが無い（kugiriは区切る/再開のみ）→終わった案件も24hは再開候補に混ざる ②同一案件のメモが重複し（周産期6・アイリス町4・発信フローA2 4）3本枠を押し出す。

**実装案（未着手）**: ①kugiri SKILL.mdに「終了」節 ②handoff_notice.pyで同一案件名は最新1本のみ注入・旧版は_done/へ ③oyasumiで30日超を自動削除。

**Why:** 終わった案件が再開候補に出続けると毎朝の1問確認にノイズが混ざる。
