# 発信物生成のleanフロー（ブログ・SNS・ショート動画）

主担当エージェントは省略しない（品質フロア）。削るのは各Phaseの無駄だけ。目標: fact-check込み130〜170K／upstream済90〜130K。

## Phase 0: main側事前準備（1回のみ・約12〜15K）

- voice-dna.md コア抽出（一人称・定型フッター・3軸キーフレーズ）
- 元素材（Notion等）読込→主要ファクトを箇条書き化
- **アーカイブgrep（必須・スキップ禁止）**: `grep -rl "<キーワード>" ~/.claude/agents/knowledge/kusagawa_archive/{01_council,02_publications,05_resources,06_election}/` → 関連過去発言を最低3件、main側で抽出（年月・議会名・要求内容・市答弁の概略）。5K以下で完了し、「過去にこう質問してきた→今回の動きはどう位置づくか」のナラティブ素材になる。これを削るのは節約ではなく品質放棄
- 統一仕様確定: タイトル50字・5段構成・PF別文字数・出力ファイルパス
- 以上を各エージェントpromptに**直接埋込**（エージェントに再fetchさせない）

## Phase 1: リサーチ（並列2本デフォルト・約60〜80K）

- 事実調査（kameyama-researcher or ドメインexpert）＋先進事例（policy-researcher等）の2本
- 過去発言抽出エージェント（policy-archive-miner）は**オプション**（自分史・実績まとめ記事に限定）。呼ぶ場合も「強いフレーズ抽出」は依頼しない（自己引用ブロック化の温床）——「文脈整理のみ」に限定
- 各指示文にD5スコープ規律（スコープ限定・tool_uses 30回以内）を明記

## Phase 2: 生成（並列・約75K）

- blog-writer / blog-writer-normal（モードA/B判定してから）→ 約35K
- sns-content-creator → 約40K
- 指示文には「字数厳守・超過時は自動圧縮してから出力」を必ず入れる（超過を草川判断に投げると保存後やり直しになる）
- voice-dna保持は**抽象指示**に留める。「このフレーズを必ず継承」型の強制はエージェントが無理に組み込んで冗長化・自己引用化するので禁止

## Phase 2.5: 草川目視（ゲート起動前・必須）

blog-writer出力後、**ゲート起動前に草川がドラフトを目視**する。構成の気持ち悪さ（自己引用過剰等）はゲートでは検出できない。ここを飛ばすとv1保存→v2上書きの往復（80K+）が発生する。

## Phase 3: 安全ゲート（直列・約25〜55K）

- content-fact-checker: 元素材でfact-check済（upstream）なら**派生新規数値のみ**検証 → 0〜30K
- content-risk-reviewer: 事前判明の懸念点リストをpromptに明記し重点軸スキャン → 約25K
- どちらも省略は不可（ユーザー明示指示時のみ例外）

## Phase 4: 保存（1回完結・約30K）

- main側でDB ID・properties JSON・本文blocksを組み立て、notion-saverに丸ごと渡す（探索させない）
- 修正はEdit最小手数。エージェント再起動は最終手段
- D1: ドラフトは一字一句そのまま `drafts/<日付>_<テーマ>_v1.md` にWrite（フッター省略禁止——後で発覚すると追加save 30K+）
- D2: 草川承認→修正→**1回で**Notion保存

## 禁止事項

- 「トークン節約のためagent省略して直書き」（独断）
- 「最小修正で済ませる」をデフォルト提案にする
- 「フル修正 vs 軽量版」の対立軸で選択させる（lean fullが常時デフォルト）
- Phase 0のアーカイブgrepスキップ
