# policy-radar スキル

## 目的

草川の政策ワークフローを1スキルで完結:
1. **外部スキャン** — 中央省庁・三重県・他自治体の最新政策動向を定期取得
2. **亀山照合** — kameyama_context.md と突き合わせて意味のあるネタだけ抽出
3. **草川視点蓄積** — 市民の声・過去発信・社会トレンドと統合して政策候補に育成
4. **議会論点化** — 議会で使える論点として📝一般質問ネタDBへ昇格
5. **承認保存** — 草川承認後にNotion DBへ確定保存

旧 `policy-update` skill（2026-04-30〜2026-05-21）の機能を統合し、5モード化。

## 機能分担（既存skill/agentと重なるもの）

| skill/agent | カバー範囲 | 本スキルとの違い |
|---|---|---|
| `news-briefing` | 亀山/三重/関心テーマ/国政動向/iJAMP の日次ニュース | 日次・件数厳選・記事レベル、政策深掘りはなし |
| `ohayo` | 朝の一日全体ブリーフ | 集約・俯瞰、政策発掘はなし |
| `policy-researcher` agent | 他自治体先進事例調査 | オンデマンド単発、定期スキャンなし |
| `kameyama-researcher` agent | 亀山市行政側ファクト | 受動的、変化検知なし |
| `policy-synthesizer` agent | 政策統合分析 | 本スキル内で呼び出す |
| **policy-radar（本スキル）** | **5モードで政策パイプライン全体を回す** | 政策の発掘→蓄積→議会論点化のハブ |

## 起動条件

以下のいずれかが含まれる発言で起動:

### 共通トリガー
- 「policy-radar」「/policy-radar」「policy-update」（後方互換）

### モード別トリガー
- **モードA（朝スキャン）**: 「政策レーダー」「省庁スキャン」「省庁の最新」「<省庁名>の発表」「最新政策動向」「政策ネタ拾って」「国の動きで亀山にどう効く」「他自治体事例ある？」
- **モードB（深掘り）**: 「/seisaku <テーマ>」「<テーマ>の政策動向」「<テーマ>の最新事例」「<テーマ>を深掘り」
- **モードC（週次）**: 「週次政策」「今週の政策アップデート」「weekly」、自動起動（毎週月曜想定）
- **モードD（月次）**: 「月次政策」「月次棚卸し」「monthly」、自動起動（毎月1日想定）
- **モードE（オンデマンド）**: 「政策アップデート」「政策候補を更新」「政策を整理したい」「今後の政策を考えたい」

判定が付かない場合、最初に1問だけ確認。

## 入力（草川から取得・推定可能なものは推定）

- **テーマ**（モードB/E必須）
- **出力先希望**（任意） — 政策候補DB / 一般質問ネタDB / 両方

## 5モード処理フロー

---

### モードA: 朝の定期スキャン（差分検知型）

詳細は `prompts/morning_brief.md` 参照。

要点:
1. sources.yaml の全情報源を WebFetch（前回スキャン日以降）
2. kameyama_context.md の現状照合フィルタA-C適用
3. 既存ネタDB照合（重複防止）
4. 優先度判定（高3件/中5件/低2件で上限10件）
5. 重要度「高」のみチャット提示→草川承認→DB保存
6. `archive/last_scan.json` を更新

---

### モードB: テーマ深掘り（7ステップ分析）

詳細は `prompts/topic_deep_dive.md` 参照。

要点:
1. テーマ理解と前提整理（kameyama_context.md から抽出）
2. 国の方向性スキャン（sources.yaml の該当領域省庁）
3. 他自治体先進事例スキャン（policy-comparison-benchmarker / policy-researcher）
4. 7ステップ分析（国の方向性→亀山素材→接続点→提言3段階→議会論点Q1〜Q4→EBPM指標→一次資料）
5. Notion保存（後述の振分けロジック）

---

### モードC: 週次差分更新

**対象期間**: 直近7日

#### Step C-1: 既存🎯政策候補DB 確認
- 🎯政策候補DB（data_source_id: `6f1895ac-3373-43b8-97d7-7ee4aa2791e0`）を notion-fetch
- 直近30日に登録されたエントリと、ステータス「進行中」のエントリを把握
- 重複防止のため**新規追加前に既存候補と類似度を判定**

#### Step C-2: 並列調査層の起動（旧 policy-update から継承）

5並列で起動:

- **2-A. kameyama-researcher agent** — 直近7日の亀山市政（議会・行政・計画改定）
- **2-B. policy-researcher agent** — 直近7日の国政・県政・先進事例
- **2-C. 市民意見** — 📝市民意見リスト（data_source_id: `c2c34bd8-1e16-492e-aab0-d3f497d18d4d`）の直近7日新規取得
- **2-D. 過去発信** — 直近7日のブログ・SNS（草川自身の発信から差分テーマ抽出）
- **2-E. 社会トレンド** — sources.yaml の中央省庁・審議会の直近7日更新

#### Step C-3: 結果集約
- A〜E の出力を統合
- kameyama_context.md と照合（フィルタA-C）
- 既存候補との重複チェック（Step C-1 結果と比較）

#### Step C-4: policy-synthesizer agent 起動
- 全データを policy-synthesizer に渡して**3〜5本の政策候補ドラフト**を生成
- 各ドラフトに「新規 / 既存追記 / 議会論点化推奨」のタグ付与

#### Step C-5: 草川承認 → Notion振分け保存（下記「出力振分けロジック」参照）

---

### モードD: 月次棚卸し

**対象期間**: 直近30日＋既存全候補の再評価

詳細は `prompts/monthly_audit.md` 参照（**Layer 1-4 必須化版**・追加 2026-05-21）。

**4 Layer 必須実行**:

- **🔴 Layer 1: 基本計画改定動向** — sources.yaml「基本計画改定動向」セクションの20計画群（住生活/国土形成/社整/交通政策/教育振興/こども/健康/介護/医療/環境/エネルギー/温対/気候適応/国土強靱化/防災/景観/空家/地方創生2.0/都市計画/公営住宅）の直近30日変化をスキャン。閣議決定・審議会答申・パブコメ・法案提出を察知。
- **🟠 Layer 2: 審議会・分科会の議事録レベル** — 主要10審議会の直近30日議事録から「亀山に降りてくる方向性」を察知。
- **🟡 Layer 3: 法改正の進行** — 自治体に新規策定義務 or 既存計画改定義務を発生させる法改正を追跡。
- **🔴 Layer 4: 塩漬け計画 × 国動向クロス分析（最重要）** — kameyama_context.md「塩漬け計画 × 国動向クロス分析マスタ」の14計画について、対応する国計画の動向と接続して改定主導論点を抽出。**「住生活基本計画レベル」の見過ごしを構造的に防ぐ**核心ステップ。

**追加 Step D-6: 既存候補のステータス見直し提案**:
- 「進行中」のまま3か月放置 → 「Wish List」「Archive」候補として提示
- 議会論点化が進んだ候補 → 「📝一般質問ネタDB」昇格候補として提示
- 重複統合可能な候補 → マージ提案

**追加 Step D-7: kameyama_context.md 更新ログ追記** — 月次棚卸しで発見した重要動向を末尾「更新ログ」セクションに追記。次回月次棚卸し時の参照履歴になる。

**重要**: Layer 1-4 の**すべて必須**（飛ばさない）。「住生活基本計画レベルの見過ごし」を出さないことが本モードの責任。

---

### モードE: オンデマンド政策アップデート

**起動例**: 「子育てDXの政策候補を作って」「太陽光規制で動向まとめて政策候補化」

2. モードB の7ステップ分析を実行
3. モードC の並列調査層を該当テーマに限定して起動
4. policy-synthesizer で統合
5. 草川承認 → 振分け保存

## 安全ゲート（必須）

policy-radar 単独で投稿・発信用文章は生成しない。**ネタ抽出と整理のみ**。

ブログ・SNS化が必要な場合は別途以下のフローに通す（CLAUDE.md準拠）:
1. blog-writer / sns-content-creator で生成
2. `content-fact-checker` で一次情報検証
3. `content-risk-reviewer` で8軸リスクスキャン
4. 草川承認後にNotion保存

ただしNotion DB保存前の**ネタ自体に固有名詞・統計値が含まれる場合**は本スキル内で content-fact-checker をスポット起動。

## 設定ファイル

- `sources.yaml` — 監視する情報源リスト（草川が編集可能）
- `kameyama_context.md` — 亀山市の既存計画・現状ファイル（実装が進むたびに更新、最終更新 2026-05-21）
- `prompts/morning_brief.md` — 朝の定期スキャン用プロンプト（モードA）
- `prompts/topic_deep_dive.md` — テーマ深掘り用プロンプト（モードB）

## アーカイブと差分検知

- `archive/last_scan.json` — モードA最終スキャン日時とスキャン済みURL
- `archive/seen_articles.json` — 過去に拾った記事のURL/タイトル（重複検知）
- `archive/weekly_log.json` — モードC週次実行ログ（既存候補との照合履歴）
- `archive/monthly_audit.json` — モードD月次棚卸し履歴
- `output/<日付>_*.md` — 日別・モード別出力アーカイブ

## 運用ルール（CLAUDE.md準拠）

- **議事録参照**: 草川発言＋市答弁ペアのみ抽出（他議員ブロックはスキップ）
- **架空エピソード禁止**: 「ある市民が」型の感情演出はNG、実体験/一次情報/公式データのみ
- **議会・他議員への提言色を抜く**: 政策提言の宛先は執行部に限定
- **タイトル50字以内**（Notion保存時）
- **PDFバイナリは pdftotext**（WebFetchで読めない場合）
- **D5 リサーチスコープ厳守**: agent呼出時は「依頼スコープに直接答える資料に限定。voice-dna・3pillars等のローカル既存資料は明示依頼時のみ参照。tool_uses 30回以内目安」を必ず指示文に含める
- **承認なきDB保存禁止**: AI判断で勝手にNotion確定保存しない（旧 policy-update 継承）
