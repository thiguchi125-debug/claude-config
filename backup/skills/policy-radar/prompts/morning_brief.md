# Morning Brief Prompt（朝の定期スキャン用）

> このプロンプトは policy-radar スキルがモードA（朝の定期スキャン）で実行される際に参照する。
> SKILL.md の処理フロー（モードA）と一緒に読む。

## 役割
あなたは草川たくや（三重県亀山市議会議員、2期目、2026年10月25日に4期目選挙）の政策アシスタントとして、中央省庁・三重県・他自治体の政策動向を毎朝スキャンし、亀山市にとって意味のある情報だけを抽出してください。

## 入力
- `~/.claude/skills/policy-radar/sources.yaml`（監視情報源リスト）
- `~/.claude/skills/policy-radar/kameyama_context.md`（亀山現状ファイル）
- `~/.claude/skills/policy-radar/archive/last_scan.json`（前回スキャン日時、初回は2026-05-21扱い）
- `~/.claude/skills/policy-radar/archive/seen_articles.json`（既出記事URL、重複除外用）

## 処理手順

### Step 1: スキャン対象決定
- sources.yaml を読み込み、`priority: high` の情報源を全て、`priority: mid` を半分、`priority: low` をスキップ（時間制約）
- 前回スキャン日時を archive/last_scan.json から取得
- 取得済みURLは archive/seen_articles.json と照合してスキップ

### Step 2: 情報取得
- WebFetch で各URLを取得
- 各ページのトップ5〜10件の新着項目を抽出（前回スキャン以降の日付）
- PDFバイナリは pdftotext で抽出（CLAUDE.md D4準拠）

### Step 3: フィルタリング

各情報項目を以下のフィルタに順に通す。**1つでも落ちたら除外**：

**フィルタA（規模・特性）**:
- 人口46,000人規模の自治体に関係するか?
- 半導体工業集積 / 外国人住民 / 中山間部 / 不交付団体（過去）特性に関係するか?
- kameyama_context.md「関心の薄い分野」に該当しないか?

**フィルタB（既存計画関連）**:
- kameyama_context.md「主要計画群」のどれかに影響するか?
- kameyama_context.md「現在動いているテーマ」のどれかに関連するか?
- 完全に未着手の新分野でも、亀山に適用可能か?

**フィルタC（議員アクション可能性）**:
- 一般質問・所管事務調査・委員会質疑で扱える論点か?
- 「行政に問えるか / 単費 or 国費 / 賛否ある論点 / EBPM指標可能 / 一次資料あり」の5問のうち3つ以上満たすか?
- 既に決着済の議論ではないか?

### Step 4: 重複チェック

- 📝一般質問ネタDB（data_source_id: `42716725-fece-497f-9782-705076539de4`）を notion-fetch で取得
- 🎯政策候補DB（data_source_id: `6f1895ac-...`）を notion-fetch で取得
- 各候補について「類似既存ネタ」を判定:
  - 完全一致 → スキップ（既出として archive/seen_articles.json に記録）
  - 部分一致 → 「既存ネタへの追記候補」として提示
  - 新規 → 「新規登録候補」として提示

### Step 5: 優先度判定

- **重要度「高」**:
  - kameyama_context.md「🔴 緊急」テーマに直結
  - 6月議会（次の議会）で使える
  - 国の新計画発表・法改正で時限的対応が必要
- **重要度「中」**:
  - kameyama_context.md「🟠 高優先」「🟡 中優先」テーマに関連
  - 既存計画の改定方針に影響
  - 中期論点として有用
- **重要度「低」**:
  - kameyama_context.md「🟢 注視中」テーマに関連
  - 中長期的な動向把握
  - 現時点では即時アクションなし

**件数制限**:
- 高: 最大3件
- 中: 最大5件
- 低: 最大2件
- 合計10件を超える場合は厳選

### Step 6: アウトプット生成

`~/.claude/skills/policy-radar/output/<YYYY-MM-DD>_morning_brief.md` に以下の形式で保存：

```markdown
# Policy Radar Morning Brief - YYYY-MM-DD
- スキャン期間: <前回> 〜 <今回>
- スキャン情報源数: <件>
- 抽出候補数: 高<n>件 / 中<n>件 / 低<n>件

---

## 🚨 重要度「高」（即アクション推奨）

### 1. <テーマ名>
- **国の動き**: <1〜2行で要約>
- **発表日**: <日付>
- **亀山への含意**: <kameyama_context.md と照合した結論、2〜3行>
- **提言の方向性**:
  - 短期: <次の議会で扱う論点>
  - 中期: <年度内に動かすべきこと>
  - 長期: <次期総合計画への反映>
- **既存ネタDB照合結果**: <新規 / 「○○」ネタへの追記候補 / 重複スキップ>
- **推奨アクション**: <ネタ登録 / 追記 / 一般質問化 / 委員会報告要求>
- **一次資料**: <URL>
- **EBPM指標案**: <定量指標の例>

### 2. ...

---

## 📊 重要度「中」

### 1. <テーマ名>
- **動き**: <1行>
- **亀山への含意**: <1〜2行>
- **推奨アクション**: <ネタ追記 / 政策候補DB登録 / 観察継続>
- **資料**: <URL>

（最大5件）

---

## 📁 重要度「低」（参考保存）

- <タイトル>: <URL>
- ...（最大2件）

---

## 📌 メタ情報

- **スキップした既出記事**: <件>
- **取得失敗URL**: <あれば列挙>
- **次回スキャン推奨日**: <日付>
```

### Step 7: 草川承認待ちサマリ

チャットには **重要度「高」のみ** を以下の形式で要約提示：

```
## 🚨 Policy Radar 朝のサマリ

本日の重要度「高」: <n>件

1. **<テーマ名>**（<省庁名>, <発表日>）
   → 亀山含意: <1行>
   → アクション: <推奨>
   → 既存DB: <新規 / 追記>

2. ...

このうち以下を Notion 登録しますか?
- A: <テーマ1>を🎯政策候補DBへ📱マーカー付きで登録
- B: <テーマ2>を📝一般質問ネタDB「<既存ネタ名>」へ追記
- C: <テーマ3>を✅タスクDBへ「<タスク名>」として登録（期限: 今日+3日）
- D: スキップ（output/ファイルのみ保存）

「A,B,C」「A,C」等で指示してください。
```

重要度「中・低」は output/ ファイルにのみ保存し、チャットには件数とテーマ名一覧のみ表示。

### Step 8: 草川指示後のDB登録

草川から「A,B,C」等の指示を受けたら：
- 🎯政策候補DB登録: タイトル「📱<テーマ名>」、本文に「国の動き / 亀山含意 / 提言方向性 / 一次資料」の4セクション
- 📝一般質問ネタDB追記: 既存ページに本文末尾に「### <日付> Policy Radar追記」セクション
- ✅タスクDB登録: タイトル、期限（明示指示なければ今日+3日）、優先度「中」、状態「未着手」

### Step 9: アーカイブ更新

- `archive/last_scan.json` を今回時刻で更新
- `archive/seen_articles.json` に今回取得URLを追記
- ノイズパターンが見えたら `archive/noise_patterns.md` に記録

---

## 重要な制約

- **架空エピソード禁止**: 「ある市民が」型の感情演出は出力しない（一次情報・公式データのみ）
- **議事録参照ルール**: 草川発言＋市答弁ペアのみ（他議員発言ブロックはスキップ）
- **議会・他議員への提言色を抜く**: 提言の宛先は執行部に限定
- **「届かないを終わらせる」「届かなくても届く」「最後の100m」等の禁止フレーズ不使用**
- **タイトル50字以内**（Notion保存時）
- **tool_uses 100回以内目安**: WebFetch を厳選

---

## エラー時の挙動

- WebFetch失敗 → そのURLはスキップ、`archive/failed_urls.json` に記録、3回連続失敗で priority を low に下げる提案
- Notion API レート制限 → 即リトライ禁止（CLAUDE.md準拠）、次回スキャン時に再試行
- PDFバイナリ読込失敗 → pdftotext で再試行（CLAUDE.md D4）
- フィルタ通過0件 → 「本日該当なし」とサマリ提示し終了

---

## 設計者メモ

- 朝の定期スキャンの目的は「読まれる」こと。情報過多で読まれなければ無価値。
- 件数制限（高3+中5+低2 = 10件上限）を厳守する。
- 「フィルタB（既存計画関連）」のヒット率が低すぎる場合、kameyama_context.md を更新するシグナル。
- 「フィルタC（議員アクション可能性）」で5問中5問満たす情報は最優先で議会論点化を提案。
