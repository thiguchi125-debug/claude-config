# kugiri — セッションを安全に区切る

## なぜ必要か（実測）

トークン消費は **文脈サイズ × 呼び出し回数** でほぼ決まる。文脈は減らないので、区切る以外に効く手段はない。

2026-09-01〜02 の実測（セッション `e02e916f`）:

- 24.5時間・227回で **100.1M トークン**。うち**出力はわずか 0.90M（0.9%）**
- 残り99.1%は「同じ会話を毎回送り直した分」
- 文脈500K超で回した**40%の呼び出しが、コストの67%**
- 文脈988Kでは `ls` 1回もブログ1版も**同じ約1M**

区切らなかったことが唯一の出血源だった。作り直しの回数ではない。

**区切りの代償は起動時固定費の約73K だけ。文脈が140Kを超えていれば、切れば必ず得（2026-09-05：200K窓に戻したため）。**

## 起動したらまずやること

現在の文脈サイズを実測して、草川に判断材料を出す。

```bash
python3 ~/.claude/scripts/ctx_now.py
```

- **140K未満** … 「まだ切らなくてよい」と伝えて終了（無駄な区切りもコスト）
- **140K以上** … 下の Step 1 へ進む

## Step 1: 作りかけの成果物を先に保存する（最優先）

**引き継ぎメモより先にこれをやる。** メモは作り直せるが、文脈の中にしか無い原稿は /clear で消える。

1. このセッションで作った未保存の原稿・データを洗い出す
2. 保存先は CLAUDE.md 保存先マップに従う
   - AI下書き → `~/.claude/projects/-Users-kusakawatakuya/drafts/`
   - スキル生成物 → `~/outputs/`
3. **Notion・ブログ・SNS原稿を保存するなら安全ゲートは省略しない**
   （content-fact-checker → content-risk-reviewer）。
   ゲート未通過のものは「未通過」と明記してローカルの drafts/ にだけ置く。

## Step 2: 引き継ぎメモを書く

**archive/ に1本だけ書く。LAST.md は廃止（2026-09-05）。** 並行セッションが同時に区切ると1枠の `LAST.md` は相互に上書きされ、実際に同日08:19〜08:24の3セッション同時区切りで、ブログの再開セッション2本が別案件を二重に走らせた。SessionStart フックは `archive/` の24時間以内のメモを案件名付きで全部（最大3件）注入するので、ポインタは要らない。

```bash
mkdir -p ~/.claude/handoff/archive
# 時刻は手打ちせず date で取る（08:29に書いたメモに「12:00」と書いた事故あり）
F=~/.claude/handoff/archive/$(date +%Y-%m-%d_%H%M)_<案件名>.md
# 案件名はファイル名がそのまま再開時の選択肢になる。他の並行案件と区別できる固有名にする
```

`LAST.md` は作らない（作っても誰も読まない）。

**厳守：20行以内・1500字以内。** 長い引き継ぎは次セッションの起動固定費を膨らませ、区切りの効果を打ち消す。経緯・議論の再現は書かない。**次の一手が分かる最小限だけ**。

```markdown
# 引き継ぎ <YYYY-MM-DD HH:MM>

## いま何をしているか
<1〜2文。案件名と目的>

## どこまで進んだか
- <完了した事実だけ。3〜5項目>

## 次の一手
1. <具体的な動作。ファイル名・DB名・コマンドまで書く>

## 保存済みの成果物
- <絶対パス>（ゲート通過/未通過を明記）

## 注意
- <ハマりどころ・未解決の判断だけ。無ければ「なし」>
```

書いたら文字数を必ず検算する。

```bash
wc -l -m "$F"
```

超えていたら削る。削る優先順は「経緯 → 背景説明 → 完了項目の細部」。

## Step 3: 草川に区切りを促す

以下の形で、短く提示する。

```
区切りの準備ができました。
　文脈 <N>K → 次セッションは 73K から始まります（このまま100回続けると +<N/10>M）
　保存済み: <パス>
　引き継ぎ: ~/.claude/handoff/archive/<いま書いたファイル>

/clear を実行してください。
そのあと「再開」とだけ入力すれば、私が引き継ぎメモを読んで続きから始めます。
（並行して別案件も区切っている場合は、再開時に案件名を1問で確認します。「<案件名>を再開」と言えば確認なしで始まります）
```

**草川が /clear を実行するまでが区切り。** 促して終わりにしない。

## 終了モード（もう開かない案件を閉じる）

**区切り＝また開く／再開＝続きから／終了＝もう開かない。** 終了は文脈サイズに関係なく使える（140K判定はしない）。

### E1: 記録すべきものを洗い出して1回だけ提示する
**引き継ぎメモの `_done/` 退避は承認を取らず自動で先に実行する**（2026-10-13草川「完了といったら引き継ぎメモだけは自動で」）。提示リストには入れず、E3で結果を1行報告するだけ。

このセッション（＋同案件の引き継ぎメモ）から、次の4種だけを拾う。**無い種類は書かない。**

| 種類 | 保存先 |
|---|---|
| 未保存の成果物 | Step 1 と同じ（発信物はゲート省略禁止・未通過は明記） |
| 案件の結論・状態 | 関連する `memory/project_*.md` を更新＋MEMORY.md の1行（120字以内）。完了なら「完了」と書く。一時的な案件で再利用価値が無ければ作らない |
| 草川の残り手番 | 報告相手あり＝市民要望台帳 `yobo.py`／それ以外＝Todoist（期限付きは task-add 経由） |
| 今後も効く教訓 | `memory/feedback_*.md`（本当に再発しうるものだけ） |

提示の形（承認は1回）:
```
終了の前に、これだけ記録します。
　1. memory: project_〇〇.md を「完了」に更新
　2. Todoist: 「〇〇」（期限なし）
　3. 引き継ぎメモ N本を _done/ へ（<ファイル名>）
よければ「OK」、不要な番号があれば教えてください。
```

### E2: 承認分を保存 → 引き継ぎメモを退避
```bash
python3 ~/.claude/scripts/handoff_done.py <案件キーワード>          # 候補確認
python3 ~/.claude/scripts/handoff_done.py <案件キーワード> --apply  # _done/ へ移動（削除はしない）
```
キーワードは部分一致。名前の揺れ（例: 〇〇 / 〇〇_完了）も拾えるよう短めにし、**候補表示で別案件が混ざっていないか見てから** `--apply`。

### E3: 終了を伝える
```
終了しました。記録: <保存したもの1行ずつ>
このウィンドウは閉じて大丈夫です（再開候補にはもう出ません）。
```
引き継ぎメモは書かない。

## 再開側（次セッションの動作）

**通常は読む必要がない。** SessionStart フック `handoff_notice.py` が、`archive/` の24時間以内のメモ（最大3件・新しい順）の本文を案件名付きで新セッション冒頭へ自動注入する（起動直後の文脈73Kで `cat` を1回走らせると73K払うため、本文を直接入れるほうが100倍以上安い）。

**注入が複数件のとき**は、草川が案件名を言っていなければ AskUserQuestion 1問でどれを再開するか確認してから着手する。選ばなかった案件には触れない（2026-09-05に確認なしで別案件を走らせ、A-1棚卸しが2セッションで二重実行された）。

注入が無いとき（24時間超等）だけ、明示的に探す。

```bash
ls -t ~/.claude/handoff/archive/ | head -5
```

いずれにせよ「次の一手」から着手する。**前セッションの経緯を掘り返さない**（それをやると区切った意味が消える）。過去ログが要るときだけ、必要な箇所を `sed -n` で抜く。

## 📌 恒久ガードルール

1. **メモは20行・1500字以内。** 超えたら削る。長い引き継ぎは区切りの効果を打ち消す。
2. **成果物の保存はメモより先。** 順序を入れ替えない。
3. **100K未満では区切らない。** 起動固定費76Kの払い損になる。
4. **発信物を保存するなら安全ゲートは省略しない。** 区切りを急ぐことは省略の理由にならない。
5. **メモは archive/ に `date` のタイムスタンプ＋固有の案件名で1本だけ。LAST.md は作らない。** 1枠ポインタは並行区切りで消し合う（2026-09-05に3セッション同時区切りで実害）。再開側は複数件なら案件を1問で確認する。
6. **再開時に前セッションのjsonlを読み返さない。** 引き継ぎメモ（自動注入）だけで着手する。
7. **handoff配下をテストで破壊しない。** 動作確認は必ず別ディレクトリのダミーで行う（2026-09-02、実テストで別セッションの引き継ぎを消す事故を起こした）。
8. **終了は「記録を承認1回→_done/へ移動」。削除しない。** 同じ案件名の新旧メモはフックが最新1本だけ注入する（2026-09-17）。
