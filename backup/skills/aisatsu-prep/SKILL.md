# aisatsu-prep スキル

## 目的
草川たくやが「今夜〇〇で挨拶する」「明日の懇親会で話す」と発言した瞬間から、**1分〜10分の短尺挨拶原稿生成＋ファクトチェック＋Notion保存先振分け**を1パスで完了させる。手作業で発生していた「制度の数字を毎回WebFetchで取りに行く」「保存先をどのDBにするか毎回考える」「会議体マスタに登録漏れ」を吸収する。

## 起動条件
以下のいずれかが含まれる発言で起動:
- 「〇〇で挨拶」「〇〇で話す」「〇〇でスピーチ」
- 「懇親会の挨拶」「自治会総会で1分」「地区集会で話す」
- 「業界団体で挨拶」「組合で挨拶」「JCで挨拶」「賀詞交歓会」
- 「挨拶を作って」「スピーチ原稿」「冒頭挨拶」

ただし以下は他スキル/agentに委譲:
- 「街頭演説」→ daily-street-speech agent
- 「式典・祝辞・弔辞・基調講演」→ speech-writer agent
- 「議会一般質問」→ general-question-prep skill

## 入力（草川から取得）
1. **会場/団体名**（必須）— 例: 亀山建設労働組合 住宅センター
2. **主題**（必須または提案）— 例: 新築・リフォーム / 防災 / 子育て
3. **持ち時間**（必須）— 1分 / 3分 / 5分 / 10分
4. **場面**（推定可）— 懇親会 / 総会 / 賀詞交歓会 / 議会公務 / 自治会
5. **任意**: 草川の役割（来賓 / 会員 / 議員として）

## 処理フロー

### Step 1: コンテキスト読込
- `~/.claude/agents/knowledge/kusagawa_archive/04_compass/voice-dna.md`
- `~/.claude/agents/knowledge/kusagawa_archive/04_compass/policy_compass.md`
- 過去の関連挨拶: `grep -rl "<団体名>" ~/.claude/agents/knowledge/kusagawa_archive/{01_council,02_publications,05_resources,06_election}/`

### Step 2: テーマ絞り込み
主題が漠然としている場合は3〜5テーマ候補を提示し、草川に「Aで」「Bで」と選択させる。**1点突破ルール**（feedback_street_speech_one_theme_only.md 準用）。

### Step 3: 亀山市制度の自動収集
主題が決まったら、関連する亀山市の制度・補助金・計画・統計を **WebFetch で亀山市公式サイトから取得**。
- 子育て → こども家庭課・子育て支援センター
- 住宅・空き家 → 建築住宅課（住まい推進グループ）
- 防災 → 防災安全課
- 産業 → 産業振興課
- 介護 → 高齢障がい支援課

### Step 4: 原稿生成
community-rally-speaker agent を起動し、以下を厳守:
- voice-dna 整合
- 数字・固有名詞は WebFetch 取得分を使用
- 「届かなくても届く」「最後の100m」等の禁止フレーズ排除
- 他議員氏名禁止
- 架空エピソード禁止
- 持ち時間に合わせた字数（1分=300〜340字 / 3分=900〜1000字 / 5分=1500字）

### Step 5: ファクトチェックゲート（CLAUDE.md 必須ルール）
1. **content-fact-checker** agent — 数値・固有名詞・法令・統計を一次情報まで遡って検証
2. **content-risk-reviewer** agent — 公選法・個人情報・名誉毀損・差別・利益相反・品位・物議の8軸スキャン
- HIGH以上のリスク検出時は ASK_USER で本人判断
- CRITICAL検出時は即停止

### Step 6: 保存先自動振分け
場面判定で保存先を分岐:

| 場面 | メイン保存先 | クロス登録 |
|---|---|---|
| 議会公務（議案分析・委員会・所管事務調査） | 📅ミーティングノートDB | （該当委員会の関連ページ） |
| 自治会総会・市政報告会 | 🏘️自治会別訪問DB | 🎤市政報告会DB + 📅ミーティングノートDB |
| **懇親会・業界団体・労組・JC・賀詞交歓会** | **📅ミーティングノートDB** | **🗺️地域・選挙ハブ「🤝組織・業界団体接触ログ」セクションに行追加** |
| 後援会集会 | 📅ミーティングノートDB | 👥後援会員DB + 🗺️地域・選挙ハブ |
| 単発講演・式典 | 📅ミーティングノートDB | — |

### Step 7: 会議体マスタ確認
**保存前必須**: 🏛会議体マスタ（46414643-9717-404f-9572-2908c2c0a7f3）に該当団体が無ければ新規作成し、ミーティングノートDBの「会議体」relationに紐付け。

### Step 8: 草川への返信
- 原稿（モバイルでそのまま読める形式）
- 構成意図（時間配分）
- 当日アドリブ素材3〜5本
- 保存先URL一覧
- ファクトチェック結果サマリー

## 関連エージェント

- **community-rally-speaker** — 短尺アジ挨拶生成（主担当）
- **speech-writer** — フォーマル長尺スピーチ（持ち時間10分超や式典系のとき委譲）
- **content-fact-checker** — 数字・固有名詞検証
- **content-risk-reviewer** — 公選法・品位・物議の8軸スキャン
- **kameyama-researcher** — 亀山市制度の深掘り調査（必要時）

## トークン節約ルール

- WebFetch は1主題あたり**最大3 URL**まで
- 過去アーカイブgrep は1キーワードあたり**最大10ファイル**まで読込
- 原稿は字数厳守（超過時は自動圧縮、再生成しない）
- ファクトチェック・リスクレビューは1パスのみ（差し戻し再ループ禁止）
- 草川承認後に Notion 保存（v1先保存→v2上書きの往復禁止）

## アンチパターン

- ❌ 制度の数字を WebFetch せず memory/training data から書く
- ❌ 会議体マスタ未登録のまま ミーティングノートDB に保存（relation 切れ）
- ❌ 「街頭演説」「式典祝辞」を本スキルで処理（他スキル/agentに委譲）
- ❌ 1分挨拶で5テーマ並列に触れる（1点突破ルール違反）
- ❌ 数字を曖昧化したまま発言（「およそ」「多数」連発）
