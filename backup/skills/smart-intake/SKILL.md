# smart-intake — 保存先自動判別・情報迷子ゼロ

## 設計思想

「保存先を毎回考える」のをやめるためのスキル。入口（モードA）と出口（モードB）の両側を保証する：
- **入口保証**: 何を投げ込んでも正規の置き場に落ちる。判定できなくても**必ずどこかに残り**、翌朝のohayoが滞留を知らせる。
- **出口保証**: 保存した場所を忘れても、横断検索1発で見つかる。全保存はnichijo日次ログに台帳として自動記録される。

- 🗓 **期限つきで登録する場合は task-add の突合手順を通す**（想定所要を1hセッション換算→カレンダー突合→✅/⚠️/🚫判定→承認）。突合なしの `td.py add --due`、Todoist MCP `update-tasks` での期限**後付け**、`reschedule-tasks` での**明後日以降への期限設定**は PreToolUse hook が deny する。今日・明日への移動（朝の繰越・即日対応）はゲート対象外。期限なしの登録はこれまで通り。

1つの入力が複数に該当する場合（例: 会議メモの中に市民の声とタスクが混在）は**分解して複数面に振り分ける**（会議→MTGノートDB＋声→市民意見リスト＋行動→Todoist）。

### A-1b. ファイルをDriveに保存するとき（2026-08-26 v5）

「このPDF保存して」「これDriveに入れといて」「〇〇に入れといて」で起動。エンジンは
`~/.claude/agents/knowledge/kusagawa_archive/99_raw/_scripts/_root_intake.py`。

**行き先が草川の言葉で明快なとき**（「防災に入れといて」「9月議会の議案に」）:
```bash
python3 …/_root_intake.py --file "<パス>" --to "daily/01_政策素材/防災"
```
指定できる行き先は `--list-dests` で一覧が出る。存在しない行き先はエラーになるので推測で打たない。

**行き先が曖昧なとき**は、まず判定させて提示 → 承認 → 実行の2手：
```bash
python3 …/_root_intake.py --file "<パス>" --dry-run   # 行き先の提案だけ
python3 …/_root_intake.py --file "<パス>"             # 承認後に実行
```

- 迷ったら**草川に聞かずマイドライブ直下に置いておくだけでもよい**（その晩に自動で振り分けられる）。急ぎでなければこれが一番安い。
- 全部の移動は `_intake_ledger.jsonl` に記録される。「あれどこ行った？」はモードBがこの台帳も見る。
- ファイル名に名簿・個人情報・連絡先・協力者が含まれるものは**中身を読まずに** `00_名簿・個人情報/` へ隔離される（grep索引にも載らない）。

### A-2. 確認は1回だけ

判定後、保存前に必ず1回だけ提示：
```
①📅ミーティングノートDB「〇〇会議 2026-07-03」（会議体:〇〇 紐付け）
②📝市民意見リストに「〇〇の声」
③Todoist🏛議員活動「〇〇に連絡」（期限7/6）
に登録します。OK？
```
- 草川承認 → 一括保存（修正指示があれば反映してから）
- 個人情報・公選法リスク・CRITICAL検出時は content-risk-reviewer を通し、HIGH以上は草川判断を仰ぐ

### A-3. 保存台帳（迷子ゼロの核心・省略禁止）

**すべての保存の直後**に、当日のnichijo日次ログページへ以下の1行を追記する（日次ログが無ければnichijoの手順で作成）：
```
🔖 HH:MM 〈内容の要約15字以内〉 → <mention-page url="...">保存先ページ名</mention-page>（＋Todoist task IDがあれば併記）
```
- 複数面に保存した場合は保存先を「／」で並べて1行にまとめる
- この台帳により「いつ・何を・どこに」の時系列記録が自動で残る。モードBの第一検索対象

### A-4. 未分類の締めループ

- 判定不能は「📥未分類インテーク」ページ（`391cf503-a68f-8191-b218-e80fdc7aedeb`・🌅朝のダッシュボード配下）へ `- [ ] YYYY-MM-DD: 〈内容〉` 形式で追記
- ohayo v3が毎朝件数を表示（「📥未分類 N件」）。溜まったら草川と一緒に棚卸し→正規保存先へ移して `[x]` 化

## モードB: 横断検索「あれどこ？」

トリガー: 「〇〇どこ」「あれどこだっけ」「〇〇探して」「〇〇見つけて」「〇〇のメモどこ」

### 検索順（1パスで全部・見つかり次第でも全レイヤー流す）

1. **nichijo日次ログの🔖台帳** — notion-searchで直近の台帳行を検索（最速・最精度）
2. **Notion横断** — notion-search（キーワード＋関連語。[[feedback_archive_grep_keyword_expansion]]の要領で草川語彙も並列）
3. **Driveアーカイブ** — `grep -ril "<キーワード>" ~/.claude/agents/knowledge/kusagawa_archive/_index/` （PDFの中身まで検索できる高速キャッシュ）
4. **ローカル生成物** — `ls`／`grep -rl` で `~/.claude/projects/-Users-kusakawatakuya/drafts/`・`~/outputs/`・`~/publications/`
5. **夜間振り分けの台帳** — `grep "<キーワード>" ~/.claude/agents/knowledge/kusagawa_archive/99_raw/_scripts/_intake_ledger.jsonl`（2026-08-26〜。マイドライブ直下から自動で振り分けた全ファイルの元パス・先パス・判定根拠。「Driveに入れたはずなのに直下に無い」はここで解決）
6. **移動履歴** — `grep "<キーワード>" ~/Archive/_relocation_log_*.csv`（2026-07-02の大整理で移動した267件＋以後の移動記録。「前はDesktopにあったのに」はここで解決）
7. **Todoist** — `td.py list` 出力をgrep（タスク化されたものはここ）

### 出力形式

```
🔍「〇〇」の検索結果:
1. 📅ミーティングノートDB「〇〇会議」(6/28) — Notion → [リンク]
2. Drive: 日常資料アーカイブ/01_政策素材/太陽光/〇〇.pdf
3. drafts/2026-06-27_〇〇_v1.md
見つからなかった層: Todoist
```
- 候補ゼロの場合は検索に使ったキーワードを提示し、別の言い方を1回だけ草川に確認

## 燃費・安全

- モードA: 判定はローカル知識で行い、Notionクエリは保存対象DBの確認に必要な分だけ（目安5〜10call）。lean原則適用
- モードB: 各レイヤー1クエリずつ・合計10call以内目安
- Notion書込は1操作ずつ・fetch検証（[[feedback_notion_update_content_pitfalls]]）
- 重複チェック: 保存前に同一内容の既存レコードを1回検索（📝ネタDB/市民意見リスト/Todoist。既出なら参照提示して二重登録しない）
